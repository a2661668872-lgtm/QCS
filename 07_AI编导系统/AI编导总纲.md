# QCS（请出山）总纲

## 一、系统目标

把 AI 从“生成一篇文案的工具”升级为长期编导中枢：在单条内容中统筹选题、证据、大纲、画面、拍摄和复盘；在多条内容之间根据真实发布数据积累观察，并在证据充分时升级个人创作规则。

系统服务两条长期主线：

1. 学习内容创作，逐步具备合格编导的策划、结构、影像和复盘能力。
2. 建立个人 AI 自媒体账号，通过持续发布数据明确定位、受众和真正有效的内容。

## 二、当前状态

- 账号阶段：个人账号 cold-start。
- 个人账号完整预测—发布—复盘样本：0。
- 当前评分表：临时 v0，占位使用，内容形态存在错配风险。
- 当前结论：课程只能提供方法先验，还没有任何方法可称为“本账号已验证规律”。
- 当前最重要任务：连续完成前 5 条内容的编导卡、发布前预测和发布后复盘。

状态来源：`.cheat-state.json`、`predictions/`、`videos/` 和 [[当前导演规则]]。如几处数字不一致，以实际完整复盘文件为准并修正本页。

## 三、三套能力的分工

| 系统 | 负责 | 不负责 |
|---|---|---|
| `qcs`（显示名称：QCS／请出山） | 账号目标、单条编导卡、证据边界、大纲、画面、拍摄、数据诊断和规则升级 | 不重复建立素材包、DBS 专项诊断、预测日志或评分表 |
| `shengcai-content-writer` | 素材包、逐题访谈、用户确认、AI初稿和最终发布稿 | 不根据发布结果私自修改导演规则 |
| `cheat-on-content` | 打分、盲预测、拍摄登记、发布登记、复盘、受众画像和 rubric 升级 | 不替代单条内容的事实核验、编导和画面设计 |

DBS 作为专项诊断层：对标、内容、开头、口播节奏、共鸣、AI 味、标题和发布风险已经有对应 Skill 时，由 QCS（请出山）传递当前稿件、目标和边界后路由过去，不在本系统中复制一套规则。

## 四、单条内容的标准流程

```mermaid
flowchart LR
    A[想法或选题] --> B[编导卡]
    B --> C[证据与素材包]
    C --> D[大纲确认]
    D --> E[画面与拍摄设计]
    E --> F[初稿与用户改稿]
    F --> G[最终稿]
    G --> H[盲预测]
    H --> I[拍摄与发布]
    I --> J[数据复盘]
    J --> K[观察或实验假设]
    K --> L[满足门槛后升级规则]
```

### 1. 编导卡

每条内容先从 [[模板/单条编导卡模板]] 建立：

`07_AI编导系统/单条编导卡/YYYY-MM-DD_选题关键词.md`

先确认目标观众、具体问题、第一目标、目标变化、一句话主旨和唯一主要实验变量。

### 2. 写稿前

- 区分本人事实、来源说法、本人判断、课程方法和待核查信息。
- 先确定材料、大纲和画面，再生成完整稿件。
- 用户确认过的原稿好句优先原样保留。

### 3. 发布前

- 最终稿快照进入 `scripts/`。
- 未看真实数据前完成 `predictions/` 盲预测。
- 记录实际拍摄稿是否与预测稿一致。

### 4. 发布后

- 使用 [[模板/发布复盘模板]] 补齐内容目标和编导诊断。
- `cheat-retro` 负责把真实数据写入预测闭环。
- 本系统只从数据中提出观察，不改写历史预测。

## 五、内容目标

每条内容必须有第一目标：

- **拉新**：让目标用户第一次停下并发现账号价值。
- **信任**：通过真实经历、判断、来源和边界形成稳定印象。
- **行动**：推动收藏、主页访问、私信、咨询或其他明确行为。
- **实验**：测试一个清晰变量，其他指标作为风险检查。

内容可以产生多个结果，但复盘必须按第一目标判断。详细口径见 [[指标与内容目标字典]]。

## 六、规则怎样进化

证据优先级：

> 个人账号真实数据 ＞ 公司账号历史经验 ＞ 真正对标账号数据 ＞ 课程方法 ＞ AI直觉。

升级顺序：

1. 单条作品只产生观察。
2. 两条可比作品同方向，记录重复信号。
3. 三条可比作品同方向，形成候选规则并寻找反例。
4. 至少 5 条完整校准样本后，才允许正式提议升级。
5. 涉及评分表时必须全量重打并执行 `cheat-bump`，不能私改。

当前有效规则见 [[当前导演规则]]，待验证内容见 [[实验假设池]]，版本变化见 [[规则升级日志]]。

## 七、AI修改权限

AI可以在用户当前授权范围内新建编导卡、整理实验观察、提出画面与拍摄建议。

AI不能自行：

- 修改本人真实经历、数据和隐私范围。
- 改变账号核心定位。
- 覆盖用户确认的稿件或好句。
- 把课程方法直接升级为账号规律。
- 用一条视频改变正式规则。
- 事后改写发布前预测。

## 八、课程方法与校音

- 编导方法优先读取 `01_学习对象/安先生/16-安先生5.0课程学习总览.md` 与 `01_学习对象/安先生/5.0课程逐字稿校订/核心方法校订_v0.1.md`。
- 原始逐字稿只在当前卡点需要补充上下文时按节读取；使用前检查 `_校订索引.md`。
- 明确错别字、同音字、英文工具名、标点和断句可以校正；不确定的人名、术语、数字和原意必须标记待确认。
- 校订版单独保存，不覆盖原始逐字稿。未经校订或结构化的方法不得直接写成正式导演规则。

## 十、换电脑

技能源文件随 Vault 保存于：

`skills/qcs/`

换电脑后在 Vault 根目录运行：

```powershell
powershell -ExecutionPolicy Bypass -File .\skills\qcs\scripts\install.ps1
```

安装脚本只在本机 `.codex/skills/` 创建指向 Vault 技能的 Junction；如果目标已存在且不是正确链接，脚本会停止，不覆盖或删除。
