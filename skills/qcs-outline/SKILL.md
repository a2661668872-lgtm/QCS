# QCS 大纲与材料

只完成写稿前的主旨、材料取舍和推进顺序，让后续写作者有可执行的大纲，不直接生成逐字稿。

## 启动与读取

1. 找到包含 `AGENTS.md` 的 Vault 根目录，先复用当前对话已经确认的选题、事实和删留要求。
2. 完整读取根目录 `AGENTS.md` 与 `00_个人背景/定位总览_v0.1.md`。
3. 完整读取 [共享交接契约](../qcs/references/shared-contract.md)，再从 [课程映射](../qcs/references/course-map.md) 只读取 `qcs-outline` 对应行。
4. 读取 `01_学习对象/安先生/5.0课程逐字稿校订/核心方法校订_v0.1.md` 的“大纲与材料”章节。需要补充材料组织判断时，再完整读取 `01_学习对象/安先生/03-选题流程和内容思维.md`。
5. 读取当前选题卡、单条编导卡、用户指定材料或现有素材包，优先继承 `qcs-topic` 已选中的 `02_内容素材/` 路径、内部原文摘录和改写候选。
6. 只有大纲存在会改变主旨的关键材料缺口时，才按 [共享交接契约](../qcs/references/shared-contract.md) 对 `02_内容素材/` 做一次定向补充检索；不为补齐结构整库扫描或扩展到无关资料。

## 路由边界

- 需要新建素材包、逐题访谈、AI 初稿或最终稿：交给 `shengcai-content-writer`。
- 只需要诊断已有开头：交给 `dbs-hook`。
- 本 Skill 处理的是完整写稿前的“主旨—材料—顺序”，不是逐句写作。

## 最小工作流

1. 确认本条第一目标、目标观众和已经成立的选题；三者冲突且会改变大纲时，只问一个关键问题。
2. 把本条主旨压缩成一个能被材料支持的完整判断，不写成标题、口号或多个并列结论。
3. 建立材料清单，区分必要事实或证据、素材库案例或过程、原作者观点、内部原文摘录、改写候选、用户判断、可用方法、待核查项与无关支线，并保留实际来源路径。内部原文摘录不直接进入初版正文。
4. 先删除不服务主旨的材料，再检查核心因果、转折和理解桥梁是否缺失。缺口不能从语感补齐。
5. 按观众理解顺序安排不超过三个主要推进节点。每个节点必须提供新信息，并说明它怎样推动主旨。
6. 标出暂缓材料和删减理由，避免同一信息以数据、案例和解释重复三遍。
7. 用户要求保存时，只写入当前单条编导卡的主旨、材料和大纲字段；不创建第二份大纲或修改已确认正文。

## 可执行大纲

- 一句话主旨
- 第一目标与目标观众
- 必须保留的材料及作用
- 关联素材及其来源、使用方式
- 待核查或待补的证据
- 节点 1—3：观众此刻的问题 / 新信息 / 所用材料 / 怎样推进主旨
- 开头需要承诺什么（只写任务，不代写开头）
- 结尾应留下的一个认识或行动
- 删除或暂缓的支线及理由

最后按共享交接契约返回大纲、实际使用的来源、方向性缺口和完成状态。

## 不越界

- 不从第一句话开始逐句扩写，不生成完整脚本或标题候选。
- 不为了凑满三个节点补造案例、过渡、因果或个人经历。
- 不把“句子更短”当作材料过载的主要解决方案。
- 不覆盖用户确认的素材包、初稿或最终稿。

## 完成标准

- 一句话主旨只有一个核心判断，并能由现有材料支撑。
- 必要材料、证据缺口和无关支线已经分开。
- 从素材库采用的案例、观点、信息点、内部原文摘录和改写候选均保留来源，未重复整库扫描。
- 推进节点不超过三个，顺序符合观众理解过程且没有平行堆料。
- 产物可直接交给现有写稿流程或写入单条编导卡。
- 只完成大纲任务，没有自动进入下一个 Skill。
