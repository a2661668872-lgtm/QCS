# QCS 单条选题

只回答“这一条为什么值得做”，产出一张可追溯的单条选题卡，不自动进入大纲、开头或写稿。

## 启动与读取

1. 找到包含 `AGENTS.md` 的 Vault 根目录，先复用当前对话中的候选方向和用户取舍。
2. 完整读取根目录 `AGENTS.md` 与 `00_个人背景/定位总览_v0.1.md`。
3. 完整读取 [共享交接契约](../qcs/references/shared-contract.md)，再从 [课程映射](../qcs/references/course-map.md) 只读取 `qcs-topic` 对应行。
4. 读取 `01_学习对象/安先生/5.0课程逐字稿校订/核心方法校订_v0.1.md` 的“选题与创作顺序”章节。需要更多选题判断时，再完整读取 `01_学习对象/安先生/03-选题流程和内容思维.md`。
5. 读取当前候选选题、定位，以及用户实际提供或候选卡明确列出的来源文件。需要案例、信息、观点或表达补强时，再按下述规则关联检索 `02_内容素材/`。

## 路由边界

- 用户要从素材库**批量生成、去重或更新选题池**：交给 `shengcai-topic-generator`，本 Skill 不重复实现。
- 用户要检查或选择**一条**选题：继续本 Skill。
- 用户只有宽泛话题时，可把它收窄成一条可判断的选题，但不能据此虚构需求或材料。

## 关联检索 `02_内容素材`

1. 从当前方向提取选题关键词、目标用户问题、解决方式及近义概念，优先用 `rg` 在 `02_内容素材/` 的 Markdown 中定位命中；不默认读取全部素材。
2. 排除 `搜索关键词.md`、`_入库检查报告.md` 和其他文件名以 `_` 开头的辅助文件。
3. 只把具有真实标题、来源链接和可读正文的笔记作为正式内容来源；缺少字段的命中只列为待核查线索。
4. 从最相关素材中提取可服务当前选题的案例、信息点、原作者观点和金句。每项记录具体素材路径、原始链接及本条准备怎样使用。
5. 原句可摘入素材分析的“内部原文摘录”，保留准确来源，只用于理解、比较和改写，不直接写进发布初稿；进入初版正文的“改写候选”应符合用户真实立场和账号表达，不改变事实含义。
6. 本地图片影响理解或选题成立时，按笔记嵌入顺序查看；无法读取则标明路径与影响，不猜测。
7. 没有明显相关内容时报告“素材库暂无明显相关素材”，继续使用用户已有材料，不为了显得充分而硬凑来源。

## 最小工作流

1. 用一句话写出：为哪类人，用什么内容或方式，回应什么具体需求，希望产生什么反应。
2. 检查需求是否有真实线索，解决方案、判断或体验是否能由用户已有材料和关联素材支持；把“有人可能感兴趣”和“已有证据”分开。
3. 整理关联素材清单，标明案例、信息点、原作者观点、内部原文摘录、改写候选及其使用边界；相关内容不等于核心结论已经核实。
4. 找到普世入口，确认它能让目标用户判断“与我有关”，同时不把精准主题改成泛话题。
5. 判断新鲜度来自新事实、新关系、新视角还是新过程；若只剩夸张措辞或替换数字，不算新鲜度。
6. 核对账号定位、可公开范围和制作成本。多个候选并列时，只选择证据与价值更完整的一条，并说明舍弃理由。
7. 给出“可做 / 调整后可做 / 暂缓”判断。证据不足以支撑核心结论时停在缺口，不继续包装。
8. 用户要求保存时，只更新现有 `04_选题库/选题池.md` 中指定条目或当前单条编导卡；不重排、覆盖或重建既有选题。

## 单条选题卡

- 选题表达（不是发布标题）
- 目标用户与具体需求
- 本条提供的解决方案、判断或体验
- 普世入口
- 新鲜度来源
- 希望引起的主要反应
- 核心亮点与制作赌注
- 关联素材：案例 / 信息点 / 原作者观点 / 内部原文摘录 / 改写候选
- 事实、判断、待核查项
- 具体来源路径或链接
- 结论：可做 / 调整后可做 / 暂缓

最后按共享交接契约返回卡片、实际使用的来源、会改变方向的缺口和完成状态。

## 不越界

- 不把单条评论、课程判断或 AI 猜测包装成普遍需求。
- 不照搬来源标题、开头、正文或叙事腔调。
- 不生成批量候选、发布标题、封面文字、开头、大纲或全文。
- 不承诺热门、涨粉、成交或收入结果。

## 完成标准

- 选题同时包含明确需求与本条可交付的内容价值。
- 普世入口和精准用户不冲突，新鲜度来自真实材料。
- 关键事实有具体来源，缺口与用户判断已分开标注。
- 已检索相关素材或说明无需检索；内部原文摘录与改写候选清楚分开，且均保留具体来源。
- 已给出可以执行的取舍，而不是只列优缺点。
- 只完成单条选题判断，没有自动进入下一个 Skill。
