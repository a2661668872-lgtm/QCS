# QCS 路由规则

目标不是跑完一条固定流程，而是找到当前最主要的一个卡点并完成它。

## 1. 先识别阶段

按已有证据判断，不向用户重复提问：

| 已有内容 | 当前阶段 |
| --- | --- |
| 只有方向、案例或一句想法 | 想法 |
| 已说明用户需求、解决方式和来源 | 选题 |
| 已收集事实、案例、链接或个人经历 | 材料 |
| 已有主旨、取舍和推进顺序 | 大纲/编导 |
| 已有连续正文 | 初稿 |
| 用户明确说“确认”“定稿”“发布稿” | 确认稿 |
| 已有实际拍摄版本 | 已拍 |
| 已有平台链接和发布时间 | 已发布 |
| 已有播放、留存、互动、画像或评论 | 有数据 |

从当前阶段继续。专项问题可以中途进入，不要求补前置表格。

## 2. QCS 子 Skill 路由

| 请求信号 | 选择 | 不选择 |
| --- | --- | --- |
| “账号该讲什么”“人设/定位”“这条负责拉新还是转化” | `qcs-positioning` | 不直接写稿 |
| “这个选题值不值得做”“需求够不够具体”“帮我确定这条选题” | `qcs-topic` | 批量生成选题用 `shengcai-topic-generator` |
| “资料太多怎么组织”“先讲什么”“列大纲” | `qcs-outline` | 已有完整稿的衔接检查不用它 |
| “观众为什么继续看/信任/行动”“漏斗哪里断了” | `qcs-viewer-path` | 不代替逐段结构重排 |
| “整篇开头、正文、结尾怎么安排”“设计钩子和骨架” | `qcs-structure` | 只改已有开头用 `dbs-hook` |
| “太复杂”“改成人话”“术语/重复太多” | `qcs-language` | 只查 AI 味用 `dbs-ai-check` |
| “太抽象”“加场景”“让人有代入感” | `qcs-situation` | 没有真实事实时不编场景 |
| “把真实经历讲成故事”“过程没张力” | `qcs-story` | 只有观点无真实过程时先补材料或做情境 |
| “怎么拍”“分镜/景别/空间/道具/表演/导演风格” | `qcs-visual` | 不重写整篇文案 |
| “怎么引流/卖/承接”“CTA”“处理购买顾虑” | `qcs-conversion` | 发布合规检查用 `dbs-content-risk-check` |

### 近邻判断

- `qcs-topic` 判断一条选题；`shengcai-topic-generator` 批量产出并写选题池。
- `qcs-outline` 组织写稿前材料；`shengcai-content-writer` 负责素材包、访谈、初稿和定稿。
- `qcs-structure` 设计整条作品的信息推进；`dbs-hook` 只处理已有开头；`dbs-script-flow` 只诊断已有逐字稿的衔接和划走点。
- `qcs-language` 改善用户可理解性；`dbs-ai-check` 识别机械、套话和 AI 痕迹。
- `qcs-viewer-path` 判断“被看见—理解—信任—行动”的连续路径；`qcs-conversion` 只设计最后的真实商业行动与承接。
- `review` 保存和解释已发布数据；QCS 只在复盘结论之后判断下一条最该训练什么。

## 3. 外部 Skill 路由

| 明确任务 | Skill |
| --- | --- |
| 批量生成或增量补充选题池 | `shengcai-topic-generator` |
| 素材包、访谈、完整初稿或最终发布稿 | `shengcai-content-writer` |
| 找值得模仿的对标 | `dbs-benchmark` |
| 选题已定，检查内容是否讲清楚、有用 | `dbs-content` |
| 只诊断或修改开头 | `dbs-hook` |
| 检查逐字稿衔接、密度、口播流畅度和划走点 | `dbs-script-flow` |
| 检查共鸣、立场和观众代入 | `dbs-resonate` |
| 检查 AI 套话和机械表达 | `dbs-ai-check` |
| 标题、封面文字 | `dbs-xhs-title` |
| 发布前事实、合规和表达风险 | `dbs-content-risk-check` |
| 保存发布数据、创建或维护复盘 | `review` |
| 打分、预测、拍摄/发布登记、校准 | `cheat-on-content` 的对应能力 |

外部 Skill 不可用时，明确说明缺失，不在 QCS 内复制一套替代方法。

## 4. 多问题优先级

优先处理最早阻塞后续的一项：

1. 事实或来源不足；
2. 定位/第一目标不清；
3. 选题不成立；
4. 主旨与材料未收束；
5. 观看路径或整条结构问题；
6. 情境、故事、语言和画面表达；
7. 标题、封面和发布风险；
8. 发布、数据和规则升级。

这不是必须从 1 跑到 8 的流程。只要用户的问题明确且不依赖更早选择，就直接处理该问题。

## 5. 路由输出

不要只回复“应该用某 Skill”。在目标 Skill 可用时，读取并执行它。对用户的最终输出以任务结果为主；只有职责边界或调用选择能帮助理解时，才简短说明路由。
