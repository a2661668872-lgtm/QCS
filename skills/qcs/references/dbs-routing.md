# DBS 专项路由

QCS（请出山）负责整条内容的目标、证据、结构和画面判断。只有问题已经收窄到一个专项时，才转入 DBS；不要为了“多检查一遍”把所有 DBS Skill 串行调用。

## 路由表

| 用户当前问题 | 调用 |
| --- | --- |
| 找商业或账号对标、判断哪个主体值得模仿 | `dbs-benchmark` |
| 选题已定，检查内容是否讲清楚、是否有用 | `dbs-content` |
| 只检查或修改短视频开头 | `dbs-hook` |
| 检查段落衔接、信息密度、口播流畅度和划走点 | `dbs-script-flow` |
| 检查情绪、共鸣、立场和观众代入 | `dbs-resonate` |
| 扫描 AI 套话、机械结构和不自然表达 | `dbs-ai-check` |
| 生成或调整发布标题与封面标题文字 | `dbs-xhs-title` |
| 发布前检查合规、事实与表达风险 | `dbs-content-risk-check` |

## 传递材料

转入专项 Skill 时只传递完成任务需要的内容：

- 用户原始请求。
- 当前最新稿件或相关段落。
- 本条目标观众、主要任务和一句话主旨。
- 用户明确要求保留或忽略的内容。
- 已知事实边界和不能新增的内容。

专项结果返回后，用户没有要求整合时只报告诊断或候选；用户确认采用后，再写回当前稿件或编导卡。

用户明确限定“只改开头两句”“不要动正文”“只诊断不改写”等范围时，把该限制作为交接包中的最高优先级。可以把完整稿件作为匹配度上下文交给专项 Skill，但不得因此扩大修改范围、让用户重走已经完成的正文步骤，或覆盖确认稿。

## 不路由的情况

- 要为当前选题挑一条内容结构主对标，先用 `qcs-topic`；已经指定作品、要逐段拆内容结构或迁移到本条作品，用 `qcs-structure`。
- 用户已有确认标题，需要设计封面构图、素材安排和 Lovart 提示词：进入 `qcs-cover`。
- 仍不知道内容写给谁、解决什么问题或承担什么业务任务：先完成编导判断。
- 资料不足以支持事实、案例或个人经历：先补材料或标记缺口。
- 用户只需要完整素材包、访谈、初稿或最终发布稿：进入 `shengcai-content-writer`。
- 用户已经发布并提供数据：进入 `review` 或现有预测复盘闭环。

如果目标 DBS Skill 在当前环境不可用，说明缺失项并继续完成本技能能可靠处理的部分，不冒充已经执行专项诊断。
