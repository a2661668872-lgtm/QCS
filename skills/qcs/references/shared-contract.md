# QCS 共用执行契约

所有 `qcs-*` 子 Skill 共用本契约。它规定上下文、来源、文件和交接方式；专项方法留在各子 Skill 中。

## 1. 启动与上下文

1. 找到包含 `AGENTS.md` 的 Vault 根目录，完整读取项目规则与 `00_个人背景/定位总览_v0.1.md`。
2. 先使用当前对话已经给出的目标、事实、取舍和确认结果，不让用户重复回答。
3. 只读取完成当前任务需要的最新选题卡、单条编导卡、稿件、素材或复盘。
4. 设计或诊断一条具体作品时，读取 `07_AI编导系统/当前导演规则.md`；只有不清楚字段、流程或规则层级时，再读取 `07_AI编导系统/AI编导总纲.md`。
5. 需要课程方法时，先读 [course-map.md](course-map.md)，再只读对应校订章节或结构化旧课笔记。
6. 缺失信息只有在会改变产物方向时才追问，而且一次只问一个关键问题。

## 2. 共用输入包

可用信息存在多少就使用多少，不要求为了形式补齐全部字段：

- 用户原始请求与本轮唯一任务；
- 当前阶段和最新文件；
- 目标观众、第一目标与一句话主旨；
- 用户要求保留、删除、原样使用或暂不修改的内容；
- 本人事实、原始来源说法、用户分析、课程方法与待核查项；
- 隐私、客户、公司和公开范围边界。

## 3. 共用输出包

每个子 Skill 的结果至少包含：

1. **判断**：当前主要问题是什么；
2. **产物**：能直接用于编导卡、选题卡、稿件或拍摄的结果；
3. **依据**：用了哪些用户事实、文件和课程方法；
4. **缺口**：只列会改变方向的未知项；
5. **状态**：已完成，或明确还差什么才能完成。

如果用户只要候选或诊断，不自动写入文件。用户授权保存时，优先更新现有对应文件，不另建平行版本。

## 4. 唯一产物系统

- 单条选题：`04_选题库/` 现有选题池或卡片。
- 文稿：`05_内容草稿/` 现有文件。
- 发布与复盘：`06_发布复盘/`。
- 编导判断：`07_AI编导系统/单条编导卡/`。
- 个人实验与规则：`07_AI编导系统/实验假设池.md`、`当前导演规则.md` 和 `规则升级日志.md`。

不得新建第二套素材包、逐字稿、编导卡、预测、评分、受众画像、复盘或规则库。已有专门 Skill 定义的文件写入方式优先。

## 5. 来源层级

### 用户内容来源

按以下层级明确标记，不混写：

1. 用户本人真实经历与可公开数据；
2. 可追溯原始来源的明确说法；
3. 用户本人的分析或判断；
4. 课程方法；
5. 未核查或不能使用的信息。

没有来源的数据、经历、需求、效果、障碍和因果关系不得补造。匿名要求优先于表达完整性。

### `02_内容素材` 的关联复用

`02_内容素材/` 是单条创作可主动检索的素材库，不只用于批量生成选题。制作或诊断一条具体选题时，可以从中寻找相关内容、案例、信息点、观点和金句：

1. 根据当前选题、目标用户、具体问题、解决方式及其近义概念，优先用 `rg` 定位相关 Markdown，再读取少量最相关命中；不默认整库加载。
2. 排除 `搜索关键词.md`、`_入库检查报告.md` 和其他文件名以 `_` 开头的辅助文件。
3. 优先使用同时具备真实标题、来源链接和可读正文的素材。缺少来源或正文的命中只能作为待核查线索。
4. 相关笔记中的图片会改变理解或选题判断时，按嵌入顺序查看；主要来源仍记录对应 Markdown 笔记路径。
5. 对采用的材料标明它是案例、信息点、原作者观点、内部原文摘录还是关联分析，并保留具体文件路径或原始链接。
6. 金句可以摘入素材分析作为“内部原文摘录”，但只用于理解、比较和改写，不直接写进发布初稿；进入初版正文的是符合用户真实立场和账号语言的“改写候选”。不得把原作者原句标记为用户原创。
7. 没有明显相关素材时如实说明，继续使用用户已有材料，不强行建立关联。素材含义或可用范围存在会改变方向的歧义时，只问一个关键问题。

`qcs-topic` 负责围绕当前一条选题执行上述检索；`qcs-outline` 优先继承已经选中的素材，仅在关键材料缺口明确时补充检索；其他子 Skill 默认接收已选素材，不重复扫描。

### 课程方法来源

优先级：

1. `01_学习对象/安先生/5.0课程逐字稿校订/核心方法校订_v0.1.md`；
2. `01_学习对象/安先生/16-安先生5.0课程学习总览.md`；
3. `01_学习对象/安先生/01-定位和策划思维.md` 至 `07-用画面讲故事.md` 中与当前任务对应的一份；
4. 原始逐字稿只用于核对必要上下文，并先查 `_校订索引.md`。

当前原始逐字稿均未逐句对照音视频。未经方法级校订的内容不能成为硬规则；人名、术语、数字、平台结论和因果关系有疑问时标记“待确认”。

## 6. 永久排除

- 课程销售、学员成绩、讲师收入和权威背书；
- 未经当前官方资料核实的平台阈值、后台入口、算法解释和投放规则；
- 课程案例的标题、开头、原句、个人话术和叙事腔调；
- 保证热门、涨粉、成交、收入或任何确定效果的结论；
- 无法确认的人名、术语、数字、经历和因果关系。

课程只提供可迁移的方法，不提供可照搬表达。

## 7. 人机分工

- AI：检索已有材料、归类、提出选项、检查缺口和生成可编辑产物。
- 用户：确认真实事实、目标、公开边界、关键取舍和最终版本。
- 已确认好句、稿件或事实不擅自覆盖；只诊断时不写回。
- 一个子 Skill 只完成自己的任务，不自动串行运行其余子 Skill。

## 8. 规则分层

- **稳定原则**：事实、来源、隐私、原话保留和课程边界。
- **课程方法**：可用于设计与诊断，不等于账号规律。
- **实验假设**：准备由下一批作品验证，每条内容只设一个主要变量。
- **已验证规则**：达到现有升级门槛后才能写入 `当前导演规则.md`。

单条表现只产生观察。个人账号可比数据的权重高于公司旧数据、对标样本、课程方法和 AI 直觉；相关性不等于因果。

## 9. 结束与交接

完成自身产物后停止。只有用户请求继续或 QCS 重新判断时，才进入下一能力。若当前任务其实属于 DBS、shengcai、review 或 cheat-on-content，说明职责边界并把已有上下文原样带过去，不让用户重新叙述。
