# QCS 大白话与信息效率

在不改变事实、观点和用户原意的前提下，让表达更容易听懂、复述和口播。一次只处理语言与信息效率，不顺带扩展成完整创作流程。

## 触发与排除

适用：

- 某句话或一段稿子术语多、句子长、太抽象或不够普世。
- 同一意思反复解释，信息推进慢。
- 需要补一条必要的因果、转折或理解桥梁。
- 画面已经表达的信息仍被口播重复。

不适用：

- 选题、主旨或材料本身不成立：回到对应 QCS 前置 Skill。
- 需要从材料包生成完整初稿：使用 `shengcai-content-writer`。
- 只改现有开头：使用 `dbs-hook`。
- 只检查整篇逐字稿衔接和划走位置：使用 `dbs-script-flow`。
- 只诊断 AI 写作痕迹：使用 `dbs-ai-check`。

## 启动读取

1. 找到包含 `AGENTS.md` 的 Vault 根目录，完整读取 `AGENTS.md` 与 `00_个人背景/定位总览_v0.1.md`。
2. 读取 `../qcs/references/shared-contract.md` 和 `../qcs/references/course-map.md`，只加载课程映射中属于 `qcs-language` 的方法。
3. 读取 `01_学习对象/安先生/5.0课程逐字稿校订/核心方法校订_v0.1.md` 的“语言与画面分工”和“信息效率”章节；没有对应校订方法时标记限制，不从原始逐字稿猜规则。
4. 读取用户指定的最新文字版本、对应单条编导卡中的目标观众与第一目标，以及直接支撑这些句子的事实材料。
5. 用户只要求诊断时保持只读；用户明确要求改写时再给出替换稿。若要写回文件，先确认目标文件与当前版本，不覆盖用户已经确认的文本。

先复用对话中已经确认的保留句、删除要求和表达偏好。只有受众或核心含义缺失会导致两种实质不同的改法时，才一次询问一个关键问题。

## 工作流

### 1. 锁定不可改变项

列出这段文字必须保留的事实、数字、来源归属、观点、语气和用户原话。把待核查信息标记出来，不因追求顺口而补造事实或加强因果。

### 2. 定位理解负担

逐段判断问题属于哪一类：

- 术语没有翻译成目标观众熟悉的说法。
- 一句话承载太多动作、条件或转折。
- 抽象结论前缺少例子、因果或过渡。
- 同一信息换词重复。
- 画面、字幕与口播表达同一件事。
- 修辞和铺垫晚于观众需要的信息。

先报告真正影响理解的位置，不为“更短”而机械删句。

### 3. 改成可复述的大白话

- 优先使用目标观众日常会说的词和直接句式。
- 长句按一个主要动作或判断拆开，保留自然口播节奏。
- 专业词不可替代时保留准确术语，并在第一次出现时补一句简单解释。
- 抽象观点用已有事实、动作或例子承接；没有真实例子就标记缺口。
- 保留用户有辨识度且清楚的原话，不把口语统一润色成模板腔。

大白话不等于牺牲准确度，也不等于把所有句子改得一样短。

### 4. 提高信息效率

删除不承担新信息、证据、情绪或关系作用的重复；合并相同意思；把结论放到观众需要它的位置。保留理解商业链路所需的因果、转折、限制和证据，不用提高语速掩盖信息负担。

### 5. 标注语言与画面分工

只指出哪些信息适合由画面、录屏、字幕或表格承担，以及口播可因此删去什么；不在本 Skill 内设计镜头和分镜。画面无法独立说清时，保留必要口播。

### 6. 交付或写入

默认提供“原句问题—建议改法—改变理由”。用户要求完整版本时，给出可直接口播的整段稿。只有用户明确授权修改指定文件时才写回；用户已确认的发布稿需再次明确指定修改范围。

## 产物

返回：

1. **当前判断**：最主要的理解负担与优先级。
2. **替换稿**：局部替换或完整大白话版本，遵守用户请求范围。
3. **删改说明**：哪些重复被删除、哪些理解桥梁被保留或补上。
4. **语言—画面分工**：可交给画面表达的信息，以及仍需口播的部分。
5. **来源与缺口**：保留事实的路径、课程方法来源和待确认项。
6. **完成状态**：已完成，或指出会改变改写方向的唯一阻塞。

## 完成标准

- 目标观众无需额外背景即可理解，并能用自己的话复述主旨。
- 术语已翻译或获得必要解释，长句不再同时承担过多动作。
- 重复被删除，但证据、因果、转折、限制和必要理解桥梁仍完整。
- 语言与画面不机械重复，也没有越权进入镜头设计。
- 未改变事实、数字、来源归属、用户立场和指定保留句。
- 未重做选题、整条结构、完整写稿或串行调用其他 QCS 子 Skill。
