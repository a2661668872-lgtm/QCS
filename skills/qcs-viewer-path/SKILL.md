# QCS 观看与行动路径

只诊断观众从进入到行动的连续路径，并给出一个最优先修复点，不自动改写标题、开头或全文。

## 启动与读取

1. 找到包含 `AGENTS.md` 的 Vault 根目录，先复用当前对话中的目标、稿件状态和已确认取舍。
2. 完整读取根目录 `AGENTS.md` 与 `00_个人背景/定位总览_v0.1.md`。
3. 完整读取 [共享交接契约](../qcs/references/shared-contract.md)，再从 [课程映射](../qcs/references/course-map.md) 只读取 `qcs-viewer-path` 对应行。
4. 读取 `01_学习对象/安先生/5.0课程逐字稿校订/核心方法校订_v0.1.md` 的“观看与行动路径”和“信息效率”章节。需要补充漏斗判断时，再完整读取 `01_学习对象/安先生/02-短视频的流量结构.md`。
5. 读取当前单条编导卡及已有选题、大纲或最新稿件中能反映观看路径的版本。若作品已发布，只把用户给出的数据当背景证据，不在本 Skill 内完成复盘归因。

## 路由边界

- 只改现有第一句话或开头：交给 `dbs-hook`。
- 检查现有逐字稿的段落衔接、信息密度和划走位置：交给 `dbs-script-flow`。
- 已发布作品的数据诊断与归因：交给 `review` 或现有预测复盘流程。
- 本 Skill 在这些专项之前回答：观众在完整路径上最早卡在哪一层。

## 最小工作流

1. 确认本条主要处于“被看见、被理解、被信任、采取行动”中的哪个业务位置；没有明示时基于现有信息标记假设，不冒充用户决定。
2. 顺序检查四层路径：
   - **被看见**：正确的人能否迅速判断与自己有关，精准主题是否有自然的普世入口。
   - **被理解**：开头承诺是否被正文兑现，主旨、因果、转折和理解桥梁是否足够。
   - **被信任**：关键判断是否有来源、过程、边界或真实经验支撑。
   - **采取行动**：主要行动是否与内容价值一致，观众此刻是否有具体理由以及真实承接路径。
3. 检查四层之间的交接：上一层形成的期待，下一层是否继续提供新信息、过程、变化、共鸣或可用价值。
4. 找到最早且会阻断后续的一个流失点。后面的次要问题可以记录，但不与首要问题并列修改。
5. 给出内容层面的修复任务和验收信号；需要具体重写时，明确建议下一步路由，不在本 Skill 内代做。
6. 用户要求保存时，只更新当前单条编导卡的观众旅程、风险与优先修复字段。

## 不越界

- 不用课程中的平台阈值、算法解释或单项指标预测流量。
- 不把所有互动统一理解成一个结尾口令；点赞、收藏、分享、关注和咨询需要不同内容理由。
- 不生成标题公式、开头候选、完整结构或逐句润色。
- 不承诺完播、互动、涨粉或转化提升。

## 完成标准

- 已明确本条主要业务位置并完成四层连续检查。
- 找到的是最早阻断点，而不是把所有问题平铺成清单。
- 优先修复项能落到具体内容任务，并有可观察的验收信号。
- 与开头专项、逐字稿流畅度诊断和发布复盘边界清楚。
- 只完成观看路径判断，没有自动进入下一个 Skill。
