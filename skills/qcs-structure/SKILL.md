# QCS 结构设计

观察一条对标视频的内容推进，或把已经成立的内容组织成持续兑现承诺的观看过程。一次只处理整条结构，不顺带重做选题、写完整正文或执行其他专项诊断。

## 触发与排除

适用：

- 选题、核心材料和一句话主旨已基本确认，但整条内容缺少持续观看理由。
- 需要设计开头承诺、信息释放顺序、段落推进理由或自然反馈点。
- 已有大纲需要从“材料排列”升级为“观看动力”。
- 用户指定一条对标视频，希望先拆出它每段的作用；尚无自己的选题时只做观察性拆解，不强行迁移。

不适用：

- 只诊断或改写现有开头：使用 `dbs-hook`。
- 只检查现有逐字稿的衔接、密度和划走点：使用 `dbs-script-flow`。
- 要迁移到自己的作品，但材料杂乱、主旨或主要节点尚未成立：交回 `qcs-outline`；单纯拆对标不受此限制。
- 只检查共鸣、AI 味、标题或发布风险：使用对应 `dbs-*` Skill。

## 启动读取

1. 找到包含 `AGENTS.md` 的 Vault 根目录，完整读取 `AGENTS.md` 与 `00_个人背景/定位总览_v0.1.md`。
2. 读取 `../qcs/references/shared-contract.md` 和 `../qcs/references/course-map.md`，只加载课程映射中属于 `qcs-structure` 的方法。
3. 读取 `01_学习对象/安先生/5.0课程逐字稿校订/核心方法校订_v0.1.md` 的“结构优化”章节；确需补充时，再读取 `01_学习对象/安先生/04-结构的精细化处理.md`。
4. 读取当前对话中最新版本，以及本条对应的选题卡、素材包、单条编导卡或稿件；若用户指定或已有主对标、辅助稿件，定向读取对应正文与来源，不重新扫描整库。只读取完成结构任务所需的文件。
5. 需要写入编导卡时，再读取 `../qcs/references/director-card-schema.md` 和现有卡片。找不到必要文件时列出准确路径并停止写入。

优先复用用户已提供的第一目标、目标观众、主旨、保留句和禁止新增信息。只有缺失内容会改变结构方向时，才一次询问一个关键问题。

## 工作流

### 1. 区分拆解与迁移

只拆对标时，确认可读正文或视频内容与具体来源；不要求用户先提供自己的选题、主旨和案例。需要迁移到本条作品时，再确认目标观众、第一目标、一句话主旨、可用材料与证据边界。迁移条件缺失时仍可交付对标拆解，但不虚构填入自己的内容。

### 2. 拆解主对标（有对标时）

按真实转折划分片段，不套固定段数。逐段写明可定位位置、内容任务、观众此刻的问题与继续看的理由、依赖的事实或画面，以及哪些功能可迁移、哪些依赖原作者而不可直接搬。主对标决定可参考的整条推进关系；播放表现只作观察，不能证明某个节点导致爆款。只有文字稿时只拆文字与信息结构，不推测镜头、剪辑或表情。若只有对标拆解请求，到此给出观察、来源与缺口后停止。

### 3. 锁定开头承诺

用一句话说明开头让正确观众期待得到什么，并标出正文第一次用结果、证据、过程或方法实质兑现承诺的位置。如果前段只反复预告，优先考虑前移一项已有材料；不以固定秒数判定，也不擅自改写用户确认的开头。这里只处理承诺与兑现的结构关系，不执行开头文案专项改写。

### 4. 选择主要推进动力

根据真实内容选择一种主要动力，必要时搭配一种辅助动力：

- 兴趣：持续出现新的、有用的信息。
- 戏剧：真实目标、阻力、变化或悬念推动进程。
- 共鸣：具体细节让观众联想到自己。
- 逻辑：证据、转折或推理持续改变理解。
- 节奏：语言、动作、画面或声音形成张弛。
- 销售：需求、信任、顾虑与行动逐步推进。

不为套结构补造冲突、失败、身份对立或商业结果。

### 5. 建立信息释放地图

沿用已确认大纲的主要节点，依据材料选择因果、对照、递进或过程变化等合适的推进关系；这些是候选关系，不是固定公式。为每段写清：

1. 这一段回答什么问题。
2. 提供什么新信息、证据或变化。
3. 观众为什么愿意继续看下一段。
4. 它怎样改变观众对问题的理解并推进主旨，而不是平行堆放材料。

删除只重复结论、没有新增作用的段落；复杂内容必须保留必要的因果、证据和理解桥梁。

已选主对标只提供可调整的结构主线。对每个节点，从用户指定材料、选题卡已选素材及少量相关的 `02_内容素材/` 或本人已确认的 `05_内容草稿/` 中，寻找能服务本段的开头方式、观点、信息点、案例、金句思路或结尾任务。逐项标记具体来源、原片段作用、本条真实材料、拟放位置与采用或舍弃理由。一个节点无需因原稿存在某段就硬填；多篇材料应服务同一主旨，不拼贴原句。本人旧稿只有在事实和语境仍成立时才可原样复用。

### 6. 安排反馈点

根据本条第一目标，只设计与内容自然对应的主要反馈理由，例如收藏因为以后可复用、评论因为存在真实判断空间、分享因为能帮助特定关系中的人、关注因为后续持续价值明确。不要只在结尾统一索取互动，也不承诺互动或流量结果。

若借鉴其他稿件的 CTA，只借鉴它承担的反馈任务，不复制对方无法由本条兑现的福利、产品或引流承诺。

### 7. 交付或写入

默认先在对话中提供结构方案。用户已授权写入且有当前作品的编导卡时，只更新其与“大纲与观众旅程”直接相关的字段，并在结构字段下记录本条对标参考；只有对标、没有本条选题时不另建结构库。诊断请求只输出诊断，不修改文件，不覆盖用户已确认稿件。

## 产物

返回：

1. **当前判断**：只拆对标时说明它实际采用的推进关系；迁移时说明本条的主要结构问题与所选推进动力。
2. **对标拆解（有对标时）**：来源、各片段的位置与功能、可迁移关系及不可搬的依赖；原因解释标为假设。
3. **结构地图（迁移时）**：开头承诺及首次兑现位置、主要推进关系、各节点的新信息和继续观看理由、结尾带走内容。
4. **辅助片段映射（迁移时）**：每项来源身份、原作用、本条拟用节点和采用或舍弃理由。
5. **反馈点地图（迁移时）**：反馈类型、触发内容及其服务的第一目标。
6. **删减或换序说明**：指出材料为何删除、合并或后移。
7. **来源与缺口**：使用的事实路径、课程方法来源和会改变方向的待确认项。
8. **完成状态**：已完成，或准确说明仍被哪个前置条件阻塞。

## 完成标准

- 迁移到本条作品时，开头只有一个清楚承诺，能指出首次实质兑现的位置；若前段只预告，给出前移已有材料的最小调整。
- 迁移时，每个主要段落都提供新信息、证据、变化或理解推进，并能说明下一段的观看理由。
- 迁移时，主要推进关系有材料支撑；材料围绕主旨积累与释放，没有平行堆放或机械套模板。
- 迁移时，反馈点服务本条第一目标，未用虚假冲突、群体攻击或身份羞辱换停留。
- 没有越权改开头、代写全文、做逐字稿流畅度审计或串行调用其他 QCS 子 Skill。
- 用户确认句、事实、来源归属和不可新增信息均未被改写。
- 有对标时区分可观察的段落安排与待验证的效果解释；只有文字稿不编画面。
- 辅助稿件只补当前节点所需，保留具体来源与身份，不把外部原句移入初稿或将多篇稿件机械拼接。
