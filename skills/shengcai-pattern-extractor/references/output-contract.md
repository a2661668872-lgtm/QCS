# 输出与增量合并约定

本文件定义 `shengcai-pattern-extractor` 的素材有效性、汇总字段、规律文件格式和保护边界。执行 Skill 时先完整读取本文件。

## 有效素材

扫描 `02_内容素材` 下的 Markdown 文件，并排除：

- `搜索关键词.md`
- `_入库检查报告.md`
- 其他文件名以 `_` 开头的辅助文件

只有同时具备以下三项，才算有效素材：

1. 标题：Markdown 一级标题中的真实标题。
2. 来源链接：优先读取“视频链接”“笔记链接”或“来源链接”；没有标签时才使用正文中第一个明确来源网址。
3. 可读正文：优先读取 `## 正文` 区域。空白、占位语或“未提供”不算正文。

素材缺项时，不补写、不推测、不进入规律提取；在最终报告中列出路径和缺失项。

## 汇总格式

文件：`03_内容规律/_规律提取汇总.md`

每条素材使用以下字段：

```markdown
## 素材 01

- 素材文件：`02_内容素材/……/笔记信息.md`
- 标题：……
- 开头 1-3 句原文：
  - 笔记文字开头：“……”
  - 图片内容开头（01.jpg）：“……”
- 图片正文：
  - 01.jpg：“……”
  - 02.jpg：无可读文字
  - 03.jpg：无法读取；路径：`D:/……/03.jpg`；原因：文件不存在
- 正文结构：步骤一 → 步骤二 → …… → 结尾动作：……
```

约束：

- 素材文件中没有的字段写“未采集”。
- 没有嵌入图片时，“图片内容开头”和“图片正文”都写“未采集”。
- 图片按嵌入顺序写 `01.jpg、02.jpg……`，即使中间某张失败也不得改变顺序。
- 图片文字只保留会影响标题、开头和结构判断的原始文字，不把装饰元素描述成正文。
- 笔记文字开头保留原文前 1-3 句，不改写。
- 正文结构遵循原文实际段落顺序，不预先合并多个步骤，最后写出关注、评论、领取、购买或其他结尾动作；没有明确动作时如实写“无明确结尾动作”。

## 标题规律文件

文件：`03_内容规律/标题规律.md`

先列出全部来源素材的完整标题，再写“候选规律”和“单条观察”。完整标题不得截断，也不得把标签从标题中偷偷删除。

候选规律格式：

```markdown
### 规律 1：【规律名称】
- 状态：待确认
- 大白话解释：
- 适合什么内容：
- 不适合什么内容：
- 不可照搬点：
- 来源素材：
  - `具体素材文件路径 1`
  - `具体素材文件路径 2`
```

识别反复出现的元素组合，例如“工具或对象 + 数字 + 明确学习结果”，而不是因为多个标题都含有“AI”就单独形成规律。

## 开头规律文件

文件：`03_内容规律/开头规律.md`

候选规律沿用通用字段，并增加原文示例：

```markdown
### 规律 1：【规律名称】
- 状态：待确认
- 大白话解释：
- 适合什么内容：
- 不适合什么内容：
- 不可照搬点：
- 原文示例：
  - 笔记文字：“来源原文 1-2 句”
  - 图片正文（01.jpg）：“来源图片文字”
- 来源素材：
  - `具体素材文件路径 1`
  - `具体素材文件路径 2`
```

示例必须逐字保留，并标明“笔记文字”或“图片正文”，不能混淆来源。

## 正文结构规律文件

文件：`03_内容规律/正文结构规律.md`

候选规律沿用通用字段，并写明结构顺序：

```markdown
### 规律 1：【规律名称】
- 状态：待确认
- 结构顺序：环节一 → 环节二 → …… → 结尾动作
- 大白话解释：
- 适合什么内容：
- 不适合什么内容：
- 不可照搬点：
- 来源素材：
  - `具体素材文件路径 1`
  - `具体素材文件路径 2`
```

结构顺序应来自素材实际推进，不用抽象词掩盖素材里的关键步骤。

## 单条观察

只出现于 1 条素材的做法使用以下格式，不把它伪装成候选规律：

```markdown
### 观察 1：【观察名称】
- 状态：待确认
- 观察内容：
- 来源素材：`具体素材文件路径`
```

只有用户明确确认后，才把状态改成“本期可用”“以后再试”或“已删除”。

## 已删除区域

用户明确删除的规律移动到文档末尾：

```markdown
## 已删除

### 规律 X：【原规律名称】
- 状态：已删除
- 删除原因：用户确认的原始原因
- 原有内容：保留原规律字段和来源
```

不得自动恢复、换名重建或删除该历史记录。

## 待确认

三份规律文件均在末尾保留：

```markdown
## 待确认

- ……
```

列入以下内容：证据不足、来源字段不足、图片无法读取、相似规律是否应合并、单条观察是否升级，以及可能影响受保护规律语义或状态的建议。没有事项时写“- 暂无”。

## 增量合并

当用户说“我搜集了新内容，帮我更新内容规律”或表达同等意思时：

1. 通过素材路径和视频或笔记 ID 同时查重。
2. 只把新增有效素材追加到汇总，不重新生成旧素材条目。
3. 用完整汇总判断新证据属于：支持既有规律、让单条观察升级、形成新单条观察、或形成新候选规律。
4. 支持既有规律时，只追加新的来源路径和必要示例，去除重复来源，不复制整条规律。
5. 受保护规律包括所有状态为“本期可用”“以后再试”“已删除”的条目，以及用户明确确认过的文字。
6. 不改变受保护规律的名称、状态、解释、适用范围、不可照搬点和删除原因。
7. 新证据与受保护规律冲突时，把差异和素材路径写入“待确认”，不直接改原规律。
8. 没有新增有效素材时不写文件。

## 事实和措辞边界

- 只陈述素材能够支持的重复做法，不推导平台机制或必然结果。
- 禁止使用“这样一定会爆”“平台算法喜欢”“必然涨粉”等无法由素材证明的表述。
- 可以描述“在当前 N 条素材中出现了 N 次”，但不得把相关性写成因果。
- 所有生成的改写句、标题或结构示范都必须单独标注“AI 示例”。
