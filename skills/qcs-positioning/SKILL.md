# QCS 定位与人设

只完成本轮定位判断，把定位当作需要作品和反馈验证的经营蓝图，不自动继续选题、写稿或复盘。

## 启动与读取

1. 找到包含 `AGENTS.md` 的 Vault 根目录，先复用当前对话已经确认的信息。
2. 完整读取根目录 `AGENTS.md` 与 `00_个人背景/定位总览_v0.1.md`。
3. 完整读取 [共享交接契约](../qcs/references/shared-contract.md)，再从 [课程映射](../qcs/references/course-map.md) 只读取 `qcs-positioning` 对应行。
4. 读取 `01_学习对象/安先生/5.0课程逐字稿校订/核心方法校订_v0.1.md` 的“方向与定位”章节。需要补充判断时，再完整读取 `01_学习对象/安先生/01-定位和策划思维.md`；不要整批读取原始逐字稿。
5. 只读取与本轮判断直接相关的现有定位证据、单条编导卡或复盘结论。

## 先确定范围

- **账号级**：服务用户、核心价值、内容主线、人设、内容类型、风格、流量用途或账号阶段不清。
- **单条级**：账号定位已存在，但当前内容的第一目标、目标观众、定位关系或唯一实验变量不清。

两种范围会改变产物时，只问一个关键问题；否则根据已有信息完成并标出假设。

## 最小工作流

1. 把现有信息分成已确认事实、已有作品或数据证据、用户判断、待验证假设与真正缺口。
2. 账号级从“用户—价值—人设—类型—风格—流量用途”检查是否互相支持；单条级从“目标观众—具体问题—业务任务—预期变化—实验变量”检查是否对齐。
3. 只保留用户真实经历、判断方式和做事过程能够支持的人设信息；职业名称或自我标签本身不算人设证据。
4. 对照当前定位，明确哪些继续保留、哪些进入下一批作品验证、哪些目前不能成立。没有重复证据时，不把一次反馈写成定位结论。
5. 如用户要求保存，只更新现有定位文件或当前单条编导卡中的对应字段；改变账号核心定位、公开范围或个人事实前必须先让用户确认。

## 可直接使用的产物

根据范围只交付一种卡片。

### 账号定位卡

- 当前阶段与流量用途
- 核心用户及其具体问题
- 核心价值与内容主线
- 可被作品证明的人设信息
- 内容类型与风格方向
- 已确认 / 待验证 / 暂不采用
- 下一批只需验证的一个定位假设

### 单条业务位置卡

- 第一目标：拉新 / 信任 / 行动 / 实验
- 目标观众与具体问题
- 这条内容怎样证明当前定位
- 希望观众产生的一个认知或行为变化
- 唯一主要实验变量
- 事实与证据状态

最后按共享交接契约返回判断、产物、实际使用的来源、方向性缺口和完成状态。

## 不越界

- 不替用户发明产品、受众需求、个人经历或商业目标。
- 不因一条高低数据内容推翻定位，也不把课程框架当成定位公式。
- 不生成候选选题、标题、开头、完整正文或复盘结论。
- 不创建第二份定位库、受众画像库或编导卡体系。

## 完成标准

- 已明确本轮是账号级还是单条级定位。
- 每个结论都有事实、作品反馈或清楚标记的待验证状态。
- 用户、价值、人设与业务目标不存在明显冲突。
- 产物能直接用于现有定位文件或单条编导卡。
- 只完成定位任务，没有自动进入下一个 Skill。
