# AI 项目管理常用提示词指令库

> [!summary] 使用说明
> 本指令库用于配合 [[AI项目管理助手-AI执行说明书]] 使用。  
> 学员可以直接复制“快捷指令”，也可以将自己的资料和要求填入“完整指令”。  
> 正式使用前，请删除示例中的占位符，并确认资料读取范围、敏感信息和成果保存位置。

## 一、通用使用规则

### 1. 推荐输入方式

每次尽量提供以下信息中的 3～5 项：

- 项目名称；
- 当前阶段；
- 本次要解决的问题；
- 相关资料；
- 成果使用对象；
- 时间要求；
- 期望输出格式；
- 需要排除的敏感信息。

### 2. 占位符说明

提示词中的方括号代表需要替换的信息：

```text
[项目名称]
[资料或资料位置]
[目标对象]
[时间范围]
[输出格式]
[保存位置]
```

### 3. 通用质量要求

可在任意提示词末尾追加：

```text
请区分【已确认事实】【待确认事项】【存在冲突】【AI建议】。
不要补写资料中不存在的事实。
生成结果后，请列出需要我确认的内容，并建议成果的保存位置和下一步行动。
```

### 4. 权限与执行边界

```text
请先只读分析资料。
如需创建文件、修改正式项目资料、写入在线工具、发送消息、
调整负责人或截止时间，请先说明计划并等待我确认。
```

## 二、项目启动与诊断

## 指令 1：快速诊断一个项目

**适用场景：** 项目刚开始，或者项目情况比较混乱。

**快捷指令：**

```text
请帮我诊断这个项目，判断项目类型、当前阶段、主要管理问题和下一步最应该完成的事情。
```

**完整指令：**

```text
请以项目管理助手的身份，分析我提供的项目描述和资料。

项目名称：[项目名称]
当前情况：[简要描述]
最终希望交付：[交付成果]
相关资料：[粘贴内容、上传文件或提供资料位置]

请完成：
1. 判断项目类型和当前阶段；
2. 提炼项目背景、目标、范围和主要参与人；
3. 识别当前最重要的管理问题；
4. 列出信息缺口和待确认问题；
5. 推荐当前最应该完成的一项管理动作；
6. 说明需要使用哪些项目管理工具。

请不要直接搭建完整管理体系，只给出当前阶段最必要的建议。
```

**预期产出：** 项目诊断、信息缺口、优先行动、工具建议。

## 指令 2：从零散资料中整理项目背景

**适用场景：** 项目信息散落在文档、聊天和会议记录中。

**快捷指令：**

```text
请根据这些零散资料，整理项目背景、发起原因、目标、限制和待确认问题。
```

**完整指令：**

```text
以下是与[项目名称]有关的零散资料：

[粘贴或指定资料]

请先说明你实际读取了哪些资料，再提炼：
1. 项目背景和发起原因；
2. 当前要解决的问题或机会；
3. 项目目标和预期成果；
4. 已知的时间、资源和政策限制；
5. 已经确认的信息；
6. 不同资料之间的冲突；
7. 尚需向发起人、客户或团队确认的问题。

请生成一份结构清晰的《项目背景说明》，不要把推测写成事实。
```

**预期产出：** 项目背景说明、冲突信息、待确认问题。

## 指令 3：制定项目管理工作方案

**适用场景：** 需要确定如何管理和推进项目。

**快捷指令：**

```text
请根据这个项目的类型、阶段和团队情况，制定一份轻量、可执行的项目管理工作方案。
```

**完整指令：**

```text
请基于[项目名称]的资料，为我制定项目管理工作方案。

项目目标：[项目目标]
当前阶段：[项目阶段]
团队情况：[成员及协作方式]
关键时间：[时间要求]
现有工具：[正在使用的工具]
主要问题：[当前卡点]

方案需要包括：
1. 项目阶段和关键节点；
2. 每个阶段需要解决的管理问题；
3. 关键项目管理产出物；
4. 任务、进度、沟通、风险和成果的管理方式；
5. 推荐使用的最少工具组合；
6. 每项工具由谁维护、多久更新一次；
7. 当前两周的优先行动；
8. 需要我确认的事项。

请避免设计过度复杂的管理流程。
```

**预期产出：** 项目管理工作方案、工具组合、近期行动。

## 三、项目资料整理与归档

## 指令 4：生成项目资料处理计划

**适用场景：** 用户提供了一批不同格式的项目资料。

**快捷指令：**

```text
请先盘点这些项目资料，判断每份资料的用途、敏感性和处理方式，不要立即批量整理。
```

**完整指令：**

```text
请只读检查我提供的[项目名称]资料。

资料范围：[文件、文件夹或内容]

请先生成《项目资料处理计划》，包括：
1. 收到的资料清单；
2. 资料类型、来源和时间；
3. 每份资料与项目的关系；
4. 建议处理方式：保留原件、摘要、提炼需求、提取任务、整理纪要或建立索引；
5. 敏感信息和权限风险；
6. 优先处理顺序；
7. 暂不建议处理的资料；
8. 预计生成的成果。

请先等待我确认处理计划，不要修改、移动或复制原始资料。
```

**预期产出：** 项目资料处理计划。

## 指令 5：生成项目资料地图

**适用场景：** 需要知道项目有哪些资料、在哪里、有什么作用。

**快捷指令：**

```text
请为这些项目资料生成一份可追溯的项目资料地图。
```

**完整指令：**

```text
请基于已确认的资料范围，生成《项目资料地图》。

每份资料至少记录：
- 资料名称；
- 类型；
- 来源和提供人；
- 产生或更新时间；
- 原始位置或链接；
- 内容摘要；
- 对项目的用途；
- 可支持生成的项目成果；
- 敏感级别；
- 处理状态；
- 是否存在版本冲突。

最后请汇总：
1. 当前资料能够支持哪些项目工作；
2. 还缺少哪些关键资料；
3. 建议下一步优先整理什么；
4. 哪些信息需要用户确认。
```

**预期产出：** 项目资料地图、资料缺口。

## 指令 6：从聊天记录中提取项目事项

**适用场景：** 项目信息主要存在于群聊或私聊记录中。

**快捷指令：**

```text
请把这些聊天记录整理成项目结论、行动项、变更、风险和待确认问题。
```

**完整指令：**

```text
以下是[项目名称]的聊天记录：

[粘贴聊天记录]

请按照以下类别整理：
1. 已确认结论；
2. 新增需求或需求变化；
3. 行动项；
4. 负责人和截止时间；
5. 对外承诺；
6. 风险、分歧和阻塞；
7. 需要补充确认的问题；
8. 与原项目计划可能存在的冲突。

请保留关键内容的发言人和时间依据。
没有明确确认的负责人、日期和承诺请标记为【待确认】。
```

**预期产出：** 聊天记录整理、行动项、变更和风险。

## 指令 7：更新需求说明与变更记录

**适用场景：** 项目需求发生新增、删除或调整。

**快捷指令：**

```text
请根据最新沟通更新需求说明，并单独记录本次需求变更及其影响。
```

**完整指令：**

```text
请对比以下两部分信息：

原需求或原版本：[资料]
最新需求或沟通结果：[资料]

请生成：
1. 更新后的需求清单；
2. 本期范围和暂不覆盖内容；
3. 新增、删除和修改的需求；
4. 每项变更的提出人、时间和原因；
5. 对任务、排期、资源、成本和交付成果的影响；
6. 需要重新确认的负责人和日期；
7. 尚未审批的变更；
8. 建议同步更新的项目文件和看板。

请保留原版本，不要直接覆盖历史需求。
```

**预期产出：** 新版需求说明、需求变更记录、影响分析。

## 四、项目方案、计划与 PPT

## 指令 8：撰写项目方案

**适用场景：** 需要形成正式项目方案或实施方案。

**快捷指令：**

```text
请根据项目资料撰写一份能够落地执行的项目方案，并标记需要确认的信息。
```

**完整指令：**

```text
请为[项目名称]撰写项目方案。

方案使用对象：[老板、客户、团队或合作方]
希望推动的决定：[立项、批准预算、确认方案、启动执行等]
项目资料：[提供资料]
篇幅或格式：[要求]

方案需要包括：
1. 项目背景与问题；
2. 项目目标与成功标准；
3. 需求与范围；
4. 整体解决思路；
5. 关键工作模块；
6. 实施步骤；
7. 任务分工；
8. 里程碑与排期；
9. 资源需求；
10. 风险与应对；
11. 预期成果；
12. 待确认和待决策事项。

请先形成结构化底稿。对资料不足的部分不要自行编造。
```

**预期产出：** 项目方案底稿。

## 指令 9：制作项目计划书 PPT 大纲

**适用场景：** 需要立项汇报、项目启动会或客户提案。

**快捷指令：**

```text
请把项目方案转化为一份项目计划书PPT大纲，每页只表达一个核心结论。
```

**完整指令：**

```text
请将[项目方案或项目资料]转化为项目计划书 PPT 大纲。

汇报对象：[对象]
汇报目的：[目的]
汇报时长：[分钟]
希望对方做出的决定：[决定]
公司模板或视觉要求：[如有]

请输出：
1. 建议页数和叙事逻辑；
2. 每页标题，标题应尽量表达结论；
3. 每页核心信息；
4. 每页适合使用的图表、时间轴、流程图或表格；
5. 需要引用的数据和来源；
6. 演讲提示；
7. 待确认信息。

请先只生成逐页大纲，等待我确认后再生成完整PPT。
```

**预期产出：** 项目计划书逐页大纲。

## 指令 10：规划项目计划书的视觉风格

**适用场景：** PPT 内容已经确定，需要决定设计方向。

**快捷指令：**

```text
请根据汇报对象和项目特点，为这份PPT提供三套视觉风格方案。
```

**完整指令：**

```text
请根据以下信息，为[项目计划书]提供三套可选择的视觉风格方案：

使用场景：[立项、启动会、客户提案等]
目标观众：[对象]
项目类型：[类型]
品牌要求：[品牌色、Logo、字体或模板]
展示方式：[会议室投屏、线上会议、发送阅读]
喜欢或不喜欢的参考风格：[说明]

每套方案请说明：
1. 风格名称和关键词；
2. 适用理由；
3. 主色、辅助色和强调色；
4. 中文和英文字体；
5. 页面网格和留白；
6. 图表、表格、图片和图标规则；
7. 推荐页面类型；
8. 应避免的视觉效果。

请推荐其中一套，但等待我确认后再制作PPT。
```

**预期产出：** 三套视觉风格方案和推荐意见。

## 五、任务拆解与责任分工

## 指令 11：拆解项目任务

**适用场景：** 需要将项目目标转成可执行任务。

**快捷指令：**

```text
请把这个项目拆解成阶段、里程碑、任务和子任务，并明确每项任务的交付标准。
```

**完整指令：**

```text
请根据[项目目标、方案和时间要求]拆解项目任务。

请按以下层级输出：
项目阶段 → 里程碑 → 任务 → 子任务。

每项任务需要包含：
- 任务编号；
- 任务名称；
- 任务说明；
- 预期交付物；
- 完成标准；
- 建议负责人；
- 协作人；
- 前置任务；
- 计划开始时间；
- 建议截止时间；
- 优先级；
- 主要风险。

请检查是否存在遗漏、重复、顺序错误和无法验收的任务。
负责人和日期未确认时请标记为【AI建议】。
```

**预期产出：** 工作分解结构、任务候选清单。

## 指令 12：设计责任分工与 RACI

**适用场景：** 多人项目需要明确谁负责、谁审批和谁知情。

**快捷指令：**

```text
请根据项目任务和成员角色，设计责任分工表，并识别责任不清或多人负责的问题。
```

**完整指令：**

```text
请基于以下项目任务和成员信息，生成责任分工表：

项目任务：[资料]
项目成员及角色：[资料]

请使用以下角色：
- R：实际执行；
- A：最终负责或审批；
- C：需要协商；
- I：需要知会。

请检查：
1. 每项任务是否只有一个明确的最终负责人；
2. 是否存在无人负责的任务；
3. 是否存在职责重叠；
4. 审批关系是否清楚；
5. 哪些分工仍需成员确认。

请同时为每位成员生成个人任务确认摘要。
```

**预期产出：** RACI 表、责任风险、成员确认摘要。

## 指令 13：生成成员任务确认消息

**适用场景：** 任务已分配，需要执行人确认。

**快捷指令：**

```text
请为每位项目成员生成简洁的任务确认消息，让对方确认任务、交付标准和截止时间。
```

**完整指令：**

```text
请根据以下任务分配，为每位成员分别生成任务确认消息：

[任务分配表]

每条消息需要包含：
- 项目名称；
- 分配任务；
- 交付成果；
- 完成标准；
- 截止时间；
- 前置条件；
- 需要配合的人员；
- 确认选项。

确认选项统一为：
1. 已确认；
2. 需要调整截止时间；
3. 任务或交付标准不清楚；
4. 存在资源或依赖问题。

语言请简洁、友好、便于复制到群聊或私聊。
不要替成员确认任务。
```

**预期产出：** 每位成员的任务确认消息。

## 六、进度表、看板与甘特图

## 指令 14：制作项目进度管理表

**适用场景：** 项目进入执行阶段，需要持续跟踪。

**快捷指令：**

```text
请根据项目任务和排期，生成一张可导入在线协作工具的项目进度管理表。
```

**完整指令：**

```text
请基于[项目计划、任务清单和最新进展]生成项目进度管理表。

字段至少包括：
任务编号、所属阶段、任务名称、交付标准、负责人、协作人、
优先级、开始时间、截止时间、当前状态、完成进度、前置任务、
当前进展、阻塞问题、下一步动作、最近更新时间、任务确认状态、
相关资料或成果链接。

请完成：
1. 合并重复任务；
2. 标记信息缺失项；
3. 识别延期、阻塞和依赖冲突；
4. 统一任务状态；
5. 生成适合导入[飞书多维表格/Notion/Excel/其他工具]的格式；
6. 说明需要用户和成员确认的字段。

请不要把建议负责人或建议日期写成已确认信息。
```

**预期产出：** 在线表格数据、CSV/XLSX 或字段配置方案。

## 指令 15：设计项目任务看板

**适用场景：** 希望按状态或负责人直观看任务。

**快捷指令：**

```text
请基于同一份任务数据，设计项目总看板和成员个人任务视图。
```

**完整指令：**

```text
请基于项目进度管理表，为[协作工具]设计任务看板。

请输出：
1. 看板分组字段；
2. 推荐状态流程；
3. 每张任务卡需要展示的字段；
4. 项目负责人使用的全局看板；
5. 成员使用的“我的任务”视图；
6. 待确认任务视图；
7. 风险与延期视图；
8. 各视图的筛选、排序和分组规则；
9. 成员更新任务时必须填写的信息；
10. 需要设置的权限和提醒。

总进度表和所有看板必须使用同一份任务数据，不要复制多套数据。
```
