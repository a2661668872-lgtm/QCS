# 第四课精简逐字稿

> [!info] 整理说明
> 本文根据约1小时12分钟的课程直播逐字稿和9页课程PPT整理。正式授课约从00:05开始。本文保留课程核心观点、案例、演示逻辑、提示词和结论；删除课前闲聊、口语重复、操作等待和无关互动；对Codex、WorkBuddy、Obsidian、Skill、飞书等转写名称进行了校正。

## 00:05 项目不同，但管理主线相通

研发项目、培训项目、活动项目和团队业务建设项目的具体管理方法存在差异，但项目负责人需要管理的核心事项相通。

第四课不提供一套所有项目都必须按顺序执行的固定流程。项目本身具有动态性，执行过程中会持续出现新情况。项目管理助手更像一个开放式助理：用户可以在项目启动、执行或临近结束时使用，但需要知道当前希望AI协助完成什么。

前几课的Skill会按照流程引导用户完成一项明确交付。项目管理助手则预设项目管理的关键动作和原则，由用户根据真实项目灵活调用。

本课所说的“项目管理知识库”，不是研究项目管理理论的知识库，而是用于管理一个具体项目中产生的资料、过程和成果。

## 00:09 为什么AI需要项目资料与人员信息

如果项目从一开始就让AI参与，并将收到的资料、文件和过程成果持续保存，AI获得的项目背景可以接近项目负责人。

但项目资料中经常缺少一类重要信息：项目干系人。

项目负责人不仅要知道成员的姓名和角色，还需要理解：

- 谁拥有决策权；
- 谁负责执行；
- 谁会影响进度；
- 每个人的沟通方式和工作习惯；
- 组织内部的利益与资源关系。

讲师以一个持续三个月的黑客马拉松客户项目为例。作为外部项目执行负责人，虽然拿到了完整项目方案和一套项目管理方法，但仍需要在合作过程中理解甲方人员，才能用合适方式追进度、要结果和反馈问题。

AI可以基于显性资料分析项目，却难以完整理解未写进文档的人际关系和组织环境。

## 00:13 与AI协同，要认清责任边界

### 人对结果负责，AI对执行负责

AI生成的成果不理想时，可以要求它修改，但不必为了证明AI可以完成而无限反复。

讲师以30多位大会嘉宾的合集海报为例。由于原始照片有横版、竖版、形象照和生活照，AI多次修改仍无法让人物大小和位置完全一致。最终讲师先人工裁切和统一人物位置，再让AI继续完成设计。

使用AI的目标是获得更好的结果。如果人工处理关键环节更快，就应该自己动手。

### AI不够接地气，复杂决策仍由人完成

AI有正确的逻辑和分析方法，但难以处理隐性诉求、组织关系和多目标取舍。

讲师在为一家10人小公司设计AI内训方案时，AI主要依据现有课程和客户沟通记录提出方案。最终讲师判断，老板真正关心的不只是员工使用AI助理，还关心业务增长和员工能否成为独立经营单元，因此在课程中增加了业务共创环节。

这个需求并没有被客户直接说出来。它来自对公司规模、老板目标、课程场景和业务关系的综合判断。

当一个问题有多个可行方案，需要同时考虑人、资源、时机和关联目标时，最终选择仍由人完成。

### 没有成熟方法时，只说需求和问题

如果用户已经有成熟经验，可以把流程、方法和规范交给AI。

如果自己也不知道怎么完成，可以先说明需求和问题，让AI自主提出方案。AI第一版不一定完美，但可能提供用户没有预设的思路。

讲师在调整公众号排版和封面时，只提出“更简洁”的需求，没有指定具体颜色和布局，AI反而生成了更符合预期的版本。

如果AI自由发挥效果不好，可以再提供自己的标准，或让AI寻找可参考的Skill。

## 00:23 通过多个角色控制上下文

讲师将公众号内容生产拆成多个AI角色：

1. 内容写作助理：制定规则和标准；
2. 知识库资料整理助理：定期整理新增资料；
3. 选题策划助理：按周期生成选题；
4. 内容写作助理：负责写作、排版和封面。

这样设计是为了减少单个对话的上下文长度。对话越长，响应越慢，也越容易受到历史任务干扰。

重复执行的复杂工作可以拆成多个职责清晰的角色。每个角色只读取完成当前任务所需的规范和资料。

项目管理同样可以采用这种思路：长期复杂项目不必把所有工作塞进一个无限增长的对话，而应将稳定背景和关键成果沉淀到项目资料和工作包中，让新对话重新读取。

## 00:30 AI项目助理管五件事

讲师将AI项目助理的工作概括为五类。

### 管资料

```text
请帮我创建一个项目资料知识库。
```

将项目背景、方案、组织资料、过程文件、新增物料和最终成果集中管理，方便后续查找和调用。

### 管过程

```text
请帮我创建一个项目管理工作包。
```

保存项目执行中形成的思路、方法、重要决定、会议结论、风险、变更和复盘。

### 管任务

```text
请帮我设计项目进度管理甘特图和项目任务看板。
```

AI可以拆解项目阶段、里程碑、任务、负责人、时间和交付标准。

### 管进度

```text
请帮我设计任务进度提醒机制，分为每日待办和每周待办。
```

AI根据任务计划提醒当前工作、未完成事项、延期风险和下一阶段重点。

### 管结果

```text
请帮我撰写项目进度日报、周报或月报。
请帮我完成项目整体复盘。
```

AI将过程信息整理成进度同步、阶段汇报、风险报告和项目复盘。

## 00:33 项目管理助手不会自动理解所有责任边界

AI可以根据资料制定项目方案、拆解任务和制作管理工具，但项目负责人必须告诉AI自己的角色。

同一个项目中，内部负责人、总经理助理、外部顾问和执行成员可以调动的资源和承担的责任不同。

如果负责人、日期和承诺没有明确资料依据，AI不应把建议直接写成已经确认的项目事实。

项目管理助手负责支持执行，项目负责人负责：

- 判断目标和范围；
- 确认责任分工；
- 协调资源；
- 处理组织关系；
- 做关键决策；
- 对最终结果负责。

## 00:43 个人长期工作如何使用项目工作包

第一类场景是个人复杂或长期工作，例如课程研发、内容系统建设和业务项目。

项目工作包可以在三个时机建立和更新：

1. **立项时**：沉淀项目背景、目标和初始思路；
2. **过程节点**：一次对话形成了对项目有价值的成果或经验；
3. **关键事项**：当前结论会被后续其他任务继续调用。

讲师在每次课程结束后，会结合逐字稿和自己的思考完成课程复盘，形成课程设计经验与迭代优化方案。

下一次调整课程时，AI先读取工作包，就能知道：

- 以前发现过哪些问题；
- 哪些思路没有采用；
- 当前版本为什么这样设计；
- 下一轮应该重点改什么。

用户只需要多做一个动作：当一次对话产生了有价值的结果时，让AI将经验总结并保存到工作包。

工作包不是单纯的成果文件夹，它保存的是项目如何演进，以及未来继续工作所需的可信上下文。

## 00:49 资料多且持续新增时建立项目知识库

第二类场景是项目资料数量多，并且后续持续增加。

讲师以大会宣传海报项目为例。项目中包含大会日程、嘉宾信息、嘉宾照片、官方要求和后续新增素材。AI将资料整理为项目知识库，并提炼信息总表，区分原始制作资料、新增素材和已完成海报。

项目资料知识库的价值包括：

- 人更容易找到文件；
- AI更容易理解资料之间的关系；
- 新资料有明确保存位置；
- 已完成成果能够持续沉淀；
- 后续制作新物料时可以复用。

首次提供大量资料后，可以说：

```text
请帮我将项目相关资料整理成一个知识库，
方便后续资料更新和成果物沉淀。
```

以后每次新增物料并完成当前任务后，可以说：

```text
请将我新提供的资料沉淀到项目知识库中。
```

正式移动、覆盖或批量整理资料前，应先确认目录和处理方案。

## 00:53 项目负责人如何启动AI项目管理助手

第三类场景是以项目负责人身份管理复杂项目。

适用角色包括：

- 项目经理；
- 业务团队负责人；
- 总经理助理或董办角色；
- 外部咨询顾问；
- 负责拉齐成员、追踪进度和推动交付的人。

如果只是自己完成一项短期任务，不一定需要复杂的团队甘特图和看板。

启动方式很简单：将 [[AI项目管理助手-AI执行说明书]] 提供给Codex或WorkBuddy，并要求读取执行。

助手首先说明自己可以协助管理资料、过程、任务、进度和结果，然后询问：

- 要一起管理的项目是什么；
- 项目目前处于什么状态；
- 当前最希望解决什么问题；
- 是否有1～3份关键资料。

即使项目还只有一个模糊想法，也可以说明当前真实处境，让AI先判断这个阶段最应该做什么。

## 00:56 使用AI项目管理助手的六个技巧

### 技巧一：提供资料并说明自己的角色

告诉AI自己是内部负责人、外部顾问、总经理助理还是执行成员。角色会影响AI对资源、权限、沟通和管理重点的判断。

### 技巧二：建立项目资料知识库

让AI根据项目目标和已有资料自动规划目录，满足资料汇总、过程文件和成果存储需求。

### 技巧三：建立项目执行工作包

当AI已经协助完成看板、甘特图、方案、启动会设计、汇报或其他有效成果后，让它把其中的方法、技巧和思路沉淀到工作包。

工作包不一定在项目第一天建立，也可以在出现第一个值得沉淀的成果后建立。

### 技巧四：直接描述项目管理需求

需要看板、方案、总结、邮件、会议通知或汇报时，可以直接告诉AI。

如果第一版不满意：

1. 提供自己的方法和标准；
2. 调用课程提示词库；
3. 提供参考样本；
4. 明确指出具体问题。

### 技巧五：制定项目任务提醒

可以让AI每天提供待办和进度日报，每周提供周报，提醒已到期、未完成和即将开始的任务。

提醒主要服务项目负责人。如果需要提醒团队成员，还要结合实际使用的协同工具。

### 技巧六：结合企业微信或飞书做团队提醒

团队使用在线协同工具时，可以设计项目群日报、自动提醒或在线任务看板。

这类功能可能涉及插件、授权或简单开发。是否采用取决于团队现有工作方式，不应为了自动化增加无效复杂度。

## 01:02 六条常用项目管理指令

讲师整理了六条高频指令：

```text
1. 请读取项目背景资料，整理出项目干系人和项目关键事项。

2. 请帮我判断当前项目所处阶段，制定项目管理重点。

3. 我要准备一场项目进度同步会，帮我整理汇报内容重点。

4. 帮我更新项目进度管理看板，生成下一阶段待办清单。

5. 帮我回顾项目过程，找到项目风险点和改进建议。

6. 帮我整理会议纪要，提炼执行待办事项并加入项目任务看板。
```

整理会议纪要不能只做内容摘要，重点是识别：

- 已确认决定；
- 行动项；
- 负责人；
- 截止时间；
- 交付标准；
- 风险和待确认事项。

项目负责人需要提前暴露影响进度的风险，并推动团队讨论解决方案，不能等项目失败后才发现问题。

## 01:05 如何使用项目管理提示词库

课程提供的 [[AI项目管理常用提示词指令库]] 收录了多种项目场景的完整指令。

学员不必逐条查找和手动补齐所有内容，可以将指令库保存在项目资料中，然后说：

```text
我需要完成：{项目管理任务}。
请读取提示词指令库中的相关提示词，并按提示词执行。
```

完整提示词会规定成果结构、输入资料、检查要求和输出标准，适合正式项目成果。

但提示词也是固定规范。给出过细规范后，AI可能只按模板执行；不提供规范时，AI可能发挥得更好，也可能更差。

推荐方法是：

```text
先直接说需求
→ 查看AI第一版
→ 效果不足时调用完整提示词
→ 根据真实项目继续调整
```

## 01:07 复杂项目管理的三类关键工具

### 项目执行计划表或甘特图

用于管理项目阶段、里程碑、任务依赖、负责人和计划时间。

### 项目任务管理看板与每日进度管理

用于查看任务状态、成员责任、当前待办、延期和阻塞。

### 项目进度复盘与风险预警报告

用于周报、进度会、阶段复盘和管理决策，提前发现项目风险并提出改进建议。

项目管理助手不仅可以生成本地表格，还可以根据团队需要创建飞书在线表格或任务看板。

如果工具尚未安装，AI可以引导安装和授权。正式写入在线工具或修改团队任务前，需要用户确认。

---

## 01:09 项目成果不一定使用传统PPT

项目进度会和复盘会可以使用PPT、Word或Excel，也可以制作HTML网页看板。

Codex和WorkBuddy擅长生成网页。网页看板可以更清晰地展示：

- 已完成和未完成任务；
- 当前项目状态；
- 负责人和延期情况；
- 风险与下一步行动；
- 成员交付质量和及时性。

工具形式应根据汇报对象和使用场景选择。网页不一定总比PPT好，关键是信息是否准确、清晰，并能推动下一步行动。

## 01:11 课程总结

AI项目管理助手预设了项目管理中的关键动作和节点，但不会用一套固定流程限制所有项目。

学员需要掌握的不是某一个表格怎么制作，而是：

1. 明确人与AI的责任边界；
2. 知道AI项目助理可以管理资料、过程、任务、进度和结果；
3. 根据个人长期工作、资料型项目或复杂团队项目选择使用方式；
4. 先说真实需求，再按需调用提示词和规范；
5. 围绕计划、看板和复盘三类核心工具持续更新；
6. 将项目资料、决策、经验和成果沉淀为可跨对话调用的知识资产。

详细练习步骤见 [[02-AI项目管理助手使用与实践指南]]。
