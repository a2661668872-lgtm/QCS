# 第四课快速学习手册

> [!summary] 这节课的核心
> AI项目管理助手不是替项目负责人做最终决策，而是和负责人一起管理资料、过程、任务、进度和结果。人对项目结果负责，AI负责整理、分析、执行和提醒。

## 一、学完这节课，你要完成什么

| 序号 | 学习目标 | 完成标志 |
|---|---|---|
| 1 | 理解人与AI的责任边界 | 能说明哪些工作可交给AI，哪些决定必须由人完成 |
| 2 | 理解项目资料知识库与项目工作包 | 能区分“保存项目资料”和“沉淀项目管理经验” |
| 3 | 理解AI项目助理管理的五类事项 | 能从资料、过程、任务、进度、结果五个方面提出需求 |
| 4 | 掌握三类项目场景的使用方法 | 能根据自己的角色和项目复杂度选择合适方式 |
| 5 | 建立一套最小项目管理工具 | 至少完成计划表/甘特图、任务看板或进度复盘中的一项 |
| 6 | 使用项目管理助手推进真实项目 | 已提供真实资料并完成一次项目管理任务 |

## 二、与AI协同，先认清责任边界

### 2.1 人对结果负责，AI对执行负责

AI可以快速整理资料、生成方案、制作看板和分析风险，但项目负责人仍要检查结果。

如果AI反复修改仍无法达到要求，而人工处理更快、更可靠，就应该自己完成关键部分。使用AI的目的不是证明所有工作都能自动化，而是更高效地得到可用结果。

### 2.2 复杂决策仍由人完成

复杂决策的难点通常不在信息量，而在于需要同时判断：

- 人际关系与项目干系人的真实诉求；
- 权力、资源和责任边界；
- 当前时机与组织环境；
- 多个方案之间的取舍；
- 没有写进资料的隐性需求；
- 当下选择对后续工作的影响。

AI可以提供分析和备选方案，但不能代替项目负责人承担决策责任。

### 2.3 没有成熟方法时，只说需求和问题

如果已经有成熟流程、方法和标准，可以让AI按规范执行。

如果自己也不知道具体怎么做，可以先描述：

- 当前项目是什么；
- 现在遇到了什么问题；
- 希望得到什么结果；
- 有哪些明确限制。

让AI先提出方案或生成第一版成果，再根据结果反馈。过早规定过多细节，可能限制AI发挥。

## 三、AI项目助理主要管五件事

| 管理对象 | 典型需求 | 常见成果 |
|---|---|---|
| 管资料 | 帮我创建项目资料知识库 | 项目资料目录、资料地图、项目背景摘要 |
| 管过程 | 帮我创建项目管理工作包 | 决策记录、会议记录、经验沉淀、变更记录 |
| 管任务 | 帮我拆解任务并设计任务看板 | WBS、甘特图、任务看板、责任分工 |
| 管进度 | 帮我设计日/周提醒和进度跟踪机制 | 每日待办、周计划、延期提醒、进度状态 |
| 管结果 | 帮我生成进度报告并完成项目复盘 | 日报、周报、月报、阶段汇报、复盘报告 |

> [!important] 使用方法
> 不需要一次建立全部工具。先从当前最影响项目推进的问题开始，让AI完成一个真实任务，再逐步补齐管理体系。

## 四、项目资料知识库与项目工作包

### 4.1 项目资料知识库

项目资料知识库主要解决“项目资料放在哪里、如何找到、如何持续更新”。

可以包含：

- 项目方案、需求文档和背景资料；
- 公司介绍、组织架构和干系人资料；
- 会议纪要、聊天记录和补充说明；
- 嘉宾、客户、供应商、产品或物料信息；
- 项目过程中新增的文件；
- 已完成的方案、海报、报告、表格等成果。

适合资料数量多、资料类型复杂、后续持续有新增资料的项目。

### 4.2 项目工作包

项目工作包主要解决“项目是怎样推进的、哪些决定已经确认、以后如何继续”。

可以沉淀：

- 项目目标、边界和执行思路；
- 任务拆解和管理方法；
- 重要决策及其原因；
- 会议结论和行动项；
- 项目风险、问题和解决方案；
- 阶段成果与反馈；
- 可复用的模板、技巧和经验；
- 项目复盘与下一版改进建议。

### 4.3 两者的区别

| 对比项 | 项目资料知识库 | 项目工作包 |
|---|---|---|
| 重点 | 管理项目资料和成果物 | 管理项目过程、决策和经验 |
| 主要问题 | 资料在哪里、如何调用 | 项目怎样推进、为什么这样做 |
| 更新时机 | 收到新资料、生成新成果时 | 形成关键结论、经验或变化时 |
| 使用价值 | AI快速理解项目 | 跨对话恢复、复用经验、持续迭代 |

## 五、三类适用场景

### 5.1 个人复杂或长期工作

适合课程研发、内容系统建设、业务建设等需要持续迭代的工作。

重点使用项目工作包，沉淀：

- 立项时的背景和思路；
- 每次对话形成的有效成果；
- 后续任务会调用的方法和结论；
- 复盘、迭代和改进建议。

### 5.2 资料多且持续新增的工作

适合大会宣传、客户项目、活动策划、产品资料管理等场景。

重点建立项目资料知识库，将原始资料、新增物料和最终成果按用途整理，方便人和AI持续查找与调用。

### 5.3 项目负责人管理复杂项目

适合总经理助理、部门负责人、项目经理、外部顾问等角色。

重点管理：

- 项目阶段与当前重点；
- 任务拆解与责任分工；
- 进度、风险和阻塞；
- 成员协同和会议；
- 阶段汇报与结果复盘。

如果只是个人短期执行任务，不一定需要建立复杂的项目管理表。

## 六、使用AI项目管理助手的六个技巧

1. **先提供少量关键资料，并说明自己的角色。**  
   角色会影响AI对权限、资源和责任范围的判断。

2. **建立项目资料知识库。**  
   让AI根据项目特点规划资料目录，而不是套用固定模板。

3. **形成首个有效成果后建立项目工作包。**  
   将项目方法、思路、决策和成果持续沉淀。

4. **有需求时直接描述。**  
   看板、方案、总结、会议、邮件和汇报都可以先让AI提出第一版。

5. **建立日/周进度提醒。**  
   让AI每天提醒待办、每周整理进展，并提醒未完成和延期事项。

6. **按团队实际工具设计协同机制。**  
   团队使用飞书或企业微信时，可以进一步设计在线表格、群提醒和自动同步；团队不用这些工具时，不必为了自动化增加复杂度。

## 七、复杂项目管理的三类关键工具

### 7.1 项目执行计划表或甘特图

用于看清：

- 项目阶段和里程碑；
- 任务先后关系；
- 负责人和计划时间；
- 关键路径和延期影响。

### 7.2 项目任务看板与每日进度管理

用于跟踪：

- 待处理、进行中、待确认、已完成和已延期任务；
- 每位成员当前负责什么；
- 今天和本周需要完成什么；
- 哪些任务存在阻塞。

### 7.3 项目复盘与风险预警报告

用于提前发现：

- 哪些任务可能延期；
- 哪些成员或资源成为瓶颈；
- 哪些需求发生变化；
- 哪些结果质量不达标；
- 下一阶段需要调整什么。

工具可以是Markdown、Excel、飞书多维表格、PPT，也可以是HTML网页看板。形式不是重点，能支持团队理解、行动和决策才是重点。

## 八、六条高频提示词

```text
1. 请读取项目背景资料，整理项目干系人和关键事项。

2. 请判断当前项目所处阶段，并制定现阶段的项目管理重点。

3. 我要准备一场项目进度同步会，请帮我整理汇报内容重点。

4. 请根据最新进展更新项目任务看板，并生成下一阶段待办清单。

5. 请回顾项目过程，识别风险点、阻塞和改进建议。

6. 请整理会议纪要，提炼执行待办事项，并更新到项目任务看板。
```

需要更正式的成果时，可以调用 [[AI项目管理常用提示词指令库]]：

```text
我需要完成：{具体任务}。
请读取《AI项目管理常用提示词指令库》中的相关指令，
结合当前项目资料执行，并标记需要我确认的信息。
```

提示词是参考规范，不是不可调整的固定程序。AI第一版效果好时可以直接使用；效果不理想或成果要求较高时，再补充完整指令和标准。

## 九、常见误区

| 常见误区 | 正确做法 |
|---|---|
| AI生成的方案可以直接采用 | 项目负责人检查事实、关系、资源和后果 |
| 必须把所有工作交给AI | AI执行不理想且人工更快时，及时改为人工 |
| 一开始建立完整复杂体系 | 从当前最紧迫的管理问题开始 |
| 项目资料知识库就是工作包 | 一个管资料，一个管过程和经验 |
| 只让AI生成看板，不持续更新 | 在会议、进展变化和新增任务后及时更新 |
| 提示词越复杂越好 | 先直接说需求，必要时再调用规范 |
| 自动提醒越多越好 | 提醒必须服务真实管理节奏，避免信息噪音 |
| AI发现风险就等于风险已解决 | 风险仍需项目负责人推动决策和资源协调 |
