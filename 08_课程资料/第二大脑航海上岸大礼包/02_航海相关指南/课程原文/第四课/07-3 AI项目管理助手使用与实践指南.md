# AI项目管理助手使用与实践指南

> [!summary] 完成练习的核心方法
> 将 [[AI项目管理助手-AI执行说明书]] 提供给Codex或WorkBuddy，选择一个真实项目，先提供1～3份关键资料并说明自己的角色。让AI判断项目阶段和当前重点，再选择一项最需要的工具或成果完成真实练习。

## 一、练习目标

选择一个正在准备、执行或收尾的真实项目，让AI协助完成一次完整的项目管理任务。

推荐练习场景：

- 制定项目方案或项目计划；
- 拆解任务并明确责任人；
- 制作项目甘特图或任务看板；
- 整理会议纪要并更新行动项；
- 生成项目周报或进度同步材料；
- 识别风险、阻塞和延期事项；
- 完成阶段复盘或项目总结；
- 整理项目资料并建立工作包。

第一次练习只需完成一个主要场景，不必一次搭建全部项目管理体系。

---

## 二、开始前需要准备什么

| 项目 | 要求 |
|---|---|
| AI工具 | Codex或WorkBuddy，任选一个 |
| 执行说明书 | 课程提供的《AI项目管理助手-AI执行说明书》 |
| 提示词库 | 《AI项目管理常用提示词指令库》，正式任务时按需调用 |
| 真实项目 | 可以处于立项、计划、执行、收尾或复盘阶段 |
| 关键资料 | 先提供1～3份最能说明项目情况的资料 |
| 项目角色 | 说明自己是负责人、执行者、顾问、总助或其他角色 |
| 保存位置 | 建议确定项目资料和正式成果保存文件夹 |

可提供的关键资料包括：

- 项目介绍、需求文档或方案；
- 最近一次会议纪要或聊天记录；
- 当前任务清单、进度表或汇报；
- 组织架构、成员名单或责任分工；
- 已完成的阶段成果。

> [!warning] 权限与安全
> 只提供完成项目所需的资料。涉及客户隐私、商业秘密或团队敏感信息时，应明确排除范围。删除、移动、覆盖、批量修改、写入在线系统和对外发送前必须确认。

## 三、如何启动项目管理助手

1. 新建Codex或WorkBuddy对话。
2. 将《AI项目管理助手-AI执行说明书》拖入对话，或提供文件路径。
3. 发送启动指令。

```text
请读取并按照《AI项目管理助手-AI执行说明书》开始工作。

先以AI项目管理助手的身份了解我的项目。
请先询问最必要的信息，不要一次建立复杂的管理体系。
在读取更多资料、创建文件或写入在线工具前，先说明计划并让我确认。
```

启动后，AI会询问：

- 这次要管理的项目是什么；
- 项目目前处于什么状态；
- 当前最希望解决什么问题；
- 是否有1～3份关键资料。

## 四、第一次说明项目时要说什么

推荐使用下面的结构：

```text
项目名称：

项目背景和目标：

当前阶段：

我的角色：

我可以协调的人员或资源：

目前最需要解决的问题：

关键资料位置：

成果希望给谁使用：

敏感信息和权限边界：
```

不需要一次填满所有内容。信息暂时不确定时，可以明确标记“待确认”，让AI先根据已有资料分析。

项目角色尤其重要。例如：

- 内部项目负责人通常可以直接协调成员和资源；
- 总经理助理可能负责跟进、汇总和提醒，但不一定有最终决策权；
- 外部顾问需要区分甲乙方责任边界；
- 执行成员更适合管理自己的任务，不一定需要复杂的团队看板。

## 五、先判断项目阶段和当前重点

收到资料后，不要立刻要求AI建立所有表格。先让AI判断项目阶段：

```text
请读取我提供的资料，判断项目当前处于什么阶段。

请说明：
1. 你对项目目标、范围和当前状态的理解；
2. 已确认的信息、待确认信息和存在冲突的信息；
3. 当前最重要的三个管理问题；
4. 最推荐先完成的一项管理动作及理由。

先只读分析，不创建或修改文件。
```

常见阶段与管理重点：

| 项目阶段 | 管理重点 |
|---|---|
| 立项与需求 | 目标、范围、干系人、成功标准 |
| 方案与计划 | 任务拆解、里程碑、资源、责任分工 |
| 执行推进 | 任务状态、进度、沟通、阻塞和变更 |
| 阶段交付 | 成果检查、评审、汇报、待决策事项 |
| 收尾验收 | 交付清单、验收结果、遗留问题 |
| 项目复盘 | 目标达成、经验、问题、改进和复用 |

## 六、建立项目资料知识库

适合以下情况：

- 首次提供的项目资料较多；
- 文件分散在多个文件夹；
- 项目期间会持续新增资料和成果；
- 后续需要AI反复调用同一批信息。

推荐指令：

```text
请根据当前项目的目标和资料类型，设计一个项目资料知识库。

需要满足：
1. 保存原始资料，不直接覆盖；
2. 区分项目背景、过程资料、新增物料和交付成果；
3. 建立资料地图，说明每类资料的用途；
4. 便于后续新增资料和AI检索；
5. 标记敏感资料和不可对外使用的内容。

请先展示目录和迁移方案，等我确认后再创建、移动或批量整理文件。
```

后续新增资料时：

```text
请读取我这次新增的资料，说明它们与当前项目的关系。
完成当前任务后，提出应沉淀到项目资料知识库的位置。
未经确认不要移动原始文件。
```

## 七、建立项目工作包

当项目已经形成第一个有效成果、重要决定或管理方法时，可以建立项目工作包。

推荐的最小工作包：

```text
项目工作包/
├─ 00-项目总控台.md
├─ 01-项目管理方案.md
├─ 02-项目资料地图.md
├─ 03-项目进度与任务.md
├─ 04-沟通与决策记录.md
├─ 05-项目成果清单.md
└─ 06-待确认事项.md
```

不要为了完整而提前创建大量空目录。项目实际需要时，再增加会议纪要、需求变更、风险问题、阶段汇报、交付成果和项目复盘等内容。

推荐指令：

```text
请根据我们已经确认的项目背景、管理思路和本轮成果，
设计一套最小项目工作包。

重点保存：
- 已确认的项目事实；
- 当前目标、阶段和任务；
- 关键决定及原因；
- 风险、阻塞和待确认事项；
- 已完成成果与保存位置；
- 下一步行动。

请先展示目录和各文件用途，等我确认后再创建。
```

## 八、制作三类核心项目工具

### 8.1 项目计划表或甘特图

适用于项目启动、重新排期或阶段计划。

```text
请根据项目目标、交付物和现有时间要求，拆解项目任务并制作甘特图。

至少包含：
- 阶段与里程碑；
- 任务名称和任务说明；
- 前置依赖；
- 负责人；
- 计划开始和结束时间；
- 交付标准；
- 风险或待确认项。

资料中没有明确的负责人和日期时，不要自行承诺，
请给出建议并标记为待确认。
```

### 8.2 项目任务看板

适用于团队协作和日常推进。

推荐字段：

| 字段 | 用途 |
|---|---|
| 任务 | 明确要完成什么 |
| 所属阶段 | 便于按里程碑查看 |
| 负责人 | 明确唯一主要责任人 |
| 协作人 | 记录支持角色 |
| 状态 | 待处理、进行中、待确认、已完成、已延期 |
| 优先级 | 区分当前重点 |
| 截止时间 | 管理时间要求 |
| 交付标准 | 防止只完成动作、不完成结果 |
| 阻塞与风险 | 记录不能继续的原因 |
| 下一步 | 明确后续行动 |
| 最近更新 | 判断信息是否过期 |

```text
请根据项目计划和最新进展，制作项目任务看板。

先展示字段设计和任务样例。
确认后再生成Markdown表格、Excel导入表或在线协同表格。
不要将待确认任务标记为正式承诺。
```

### 8.3 风险预警与项目复盘

适用于周报、阶段汇报、进度会和项目收尾。

```text
请回顾当前项目资料、任务变化、会议结论和延期情况，
生成项目风险预警与改进建议。

请区分：
- 已发生问题；
- 高概率风险；
- 需要持续观察的信号；
- 资料不足、尚不能判断的事项。

每项风险说明影响、证据、责任角色、建议动作和最晚处理时间。
```

## 九、会议纪要、周报和阶段汇报

### 9.1 整理会议纪要

```text
请根据会议录音转写或聊天记录整理会议纪要。

重点提炼：
1. 会议目的；
2. 已确认结论；
3. 存在分歧或待确认事项；
4. 行动项、负责人、截止时间和交付标准；
5. 风险与需要升级决策的事项。

不要把讨论意见写成最终决定。
完成后提出项目任务看板的更新建议。
```

### 9.2 撰写项目周报

```text
请根据项目计划、任务看板和本周会议记录生成项目周报。

包括：
- 项目总体状态；
- 本周完成事项和关键成果；
- 与原计划的偏差；
- 风险、阻塞和影响；
- 下周计划；
- 需要负责人支持或决策的事项。

请区分事实、AI判断和待确认内容。
```

### 9.3 准备项目进度同步会

```text
我要准备一场项目进度同步会。
请整理最需要同步和决策的内容，不要只是罗列全部任务。

请输出：
- 当前总体判断；
- 已完成的重要结果；
- 关键偏差和原因；
- 最高优先级风险；
- 需要会议确认的决定；
- 会后行动项建议。
```

## 十、如何使用提示词指令库

[[AI项目管理常用提示词指令库]] 不是必须从头阅读的教材，而是一份项目场景菜单。

### 快捷使用

AI已经理解项目时，直接说：

```text
请根据最新会议记录更新项目任务看板，并生成下周待办。
```

### 正式使用

成果要提交给客户、领导或团队时：

```text
我需要撰写正式的项目阶段汇报。
请读取《AI项目管理常用提示词指令库》中对应的完整指令，
结合项目工作包和最新资料执行。

先检查资料是否充分，并列出需要我确认的信息。
```

### 找不到合适指令

```text
请根据我的项目阶段和当前问题，
从《AI项目管理常用提示词指令库》中选择最合适的指令。
请说明选择理由，再按该指令执行。
```

## 十一、建立提醒与在线协同

提醒机制应服务真实项目节奏。

可以让AI协助设计：

- 每日个人待办和到期提醒；
- 每周项目进展汇总；
- 会议前资料准备提醒；
- 逾期任务和长期未更新任务提醒；
- 阶段里程碑前的检查清单；
- 项目群中的日报或周报模板。

如果团队使用飞书、企业微信等工具，可以进一步创建在线任务看板或群提醒。正式写入在线系统、发送消息或修改团队任务前，必须先确认。

如果团队不使用在线协作平台，可以使用：

- Markdown任务看板；
- Excel或CSV导入文件；
- HTML项目看板；
- 每日/每周由AI生成的个人提醒。

## 十二、每次任务结束都要做什么

要求AI在完成任务后说明：

```markdown
## 本次完成

## 关键结论

## 建议更新的项目资料或工作包

## 待确认事项

## 风险与下一步
```

如果AI提出沉淀建议，先检查：

- 这是已确认事实还是AI建议；
- 是否包含敏感信息；
- 是否会覆盖已有正式文件；
- 保存位置是否正确；
- 是否需要保留旧版本。

确认后再写入。

## 十三、如何判断本次练习完成

- [ ] 已选择一个真实项目。
- [ ] 已说明自己的角色、权限和当前问题。
- [ ] 已提供1～3份关键资料。
- [ ] AI已判断项目阶段和当前管理重点。
- [ ] 已选择一项真实项目管理任务。
- [ ] 已生成至少一种可用成果。
- [ ] 已检查项目事实、负责人、日期和任务状态。
- [ ] 已标记待确认、冲突和AI建议。
- [ ] 已决定哪些信息应进入项目资料知识库或项目工作包。
- [ ] 已明确下一步行动。

### 推荐提交成果

- 项目背景和角色说明；
- 项目阶段诊断；
- 一项项目管理工具或成果；
- 一份风险与待确认事项清单；
- 项目资料知识库或工作包位置；
- 下一阶段行动计划。
