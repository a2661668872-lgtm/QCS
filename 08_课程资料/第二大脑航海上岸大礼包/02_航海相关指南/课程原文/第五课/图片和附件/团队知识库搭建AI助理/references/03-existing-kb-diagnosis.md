# 现有知识库诊断

## 流程

> 只读扫描 → 六维诊断 → 问题分级 → 改造方案 → 两次确认 → 分批执行 → 回归验证

默认只读，不移动、不覆盖、不删除、不发布。

## 六维诊断

1. 场景价值：用户、业务问题和价值是否明确。
2. 内容质量：来源、准确性、完整性、重复、冲突和过期。
3. 结构与检索：分类、命名、元数据、颗粒度和孤立知识。
4. 版本与权限：现行版本、失效内容、敏感隔离和角色变化。
5. 运营与责任：负责人、更新、反馈、审核和留痕。
6. 应用与效果：持续使用、来源引用、拒答和业务改善。

成熟度：

- 0：缺失；
- 1：初步；
- 2：规范；
- 3：持续优化。

每个评分必须说明证据。

## 问题分级

- P0：权限泄露、严重错误、失效高风险口径。
- P1：多版本冲突、关键知识无来源、无人负责。
- P2：目录、命名、元数据和颗粒度问题。
- P3：页面样式和低优先级体验。

## 改造策略

- 局部修复；
- 结构重组；
- 场景重构；
- 重新建设。

确认点一：诊断结论和改造策略。  
确认点二：具体创建、修改、移动、合并、暂停和归档清单。

分批实施，每批完成链接、来源、权限和测试检查。
