# 日常知识更新

## 流程

> 接收变化 → 判断类型 → 分析影响 → 生成草案 → 分级审批 → 发布测试 → 留痕复盘

## 更新类型

- 新增；
- 补充；
- 修订；
- 替代；
- 纠错；
- 失效；
- 合并；
- 权限变更。

新资料先进入候选区，不因进入文件夹而自动成为正式知识。

## 影响分析

检查：

- 相关正式知识和旧版本；
- FAQ、模板、案例、流程和测试集；
- 用户、部门和权限；
- 冲突资料；
- 生效日期和通知对象。

更新草案必须说明：

- 变更前后内容；
- 依据；
- 影响范围；
- 旧版本处理；
- 生效日期；
- 审批要求；
- 回归测试。

## 发布

审批后：

1. 更新正式知识；
2. 标记版本、生效日期和替代关系；
3. 归档或禁用旧版本；
4. 同步关联知识和测试；
5. 检查权限；
6. 记录变更；
7. 必要时通知用户。

紧急权限泄露或高风险错误先建议暂停相关知识；没有预授权时请求确认。
