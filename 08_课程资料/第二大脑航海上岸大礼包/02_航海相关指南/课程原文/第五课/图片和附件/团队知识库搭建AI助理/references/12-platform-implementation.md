# 平台落地

## 目标

将知识治理规则映射为平台中的空间、目录、页面、数据库、角色、权限和流程。

## 映射表

| 业务规则 | 平台能力 |
|---|---|
| 五层知识结构 | 空间、目录、页面、数据库 |
| 资料入口 | 文件夹、表单、上传入口 |
| 知识状态 | 草稿、待审核、已发布、失效 |
| 角色责任 | 所有者、编辑者、审核者、访问者 |
| 权限 | 空间、目录、文档或字段级控制 |
| 版本 | 页面历史、文件版本、替代关系 |
| 审批 | 流程、任务、评论和通知 |
| 反馈 | 表单、评论、工单或反馈页 |
| 运营 | 日志、统计和任务看板 |

## 实施顺序

1. 核对平台当前能力。
2. 建立最小目录和角色。
3. 配置资料入口与待审核区。
4. 迁移少量权威资料试跑。
5. 验证权限、版本、引用和更新。
6. 建立用户入口和反馈。
7. 完成试点后再扩大范围。

如果平台不支持某项治理规则，明确记录能力缺口并设计人工流程、外部表单、自动化或替代工具。不要假装平台具备不存在的能力。
