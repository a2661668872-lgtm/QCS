# 团队AI知识库运营助理使用与实践指南

> [!summary] 完成练习的核心方法
> 安装“团队AI知识库运营助理”Skill后，选择一个真实团队场景，提供业务问题、目标用户或资料位置中的任意信息。让助理先读取资料并给出推荐方案，再由你确认场景、权威口径、权限和正式发布事项。

## 一、练习目标

本次练习不要求一次建成完整企业知识库。请选择一个真实任务，完成一轮“小而可信”的实践闭环。

推荐练习：

- 判断当前团队问题是否适合建设知识库；
- 为一个部门规划首期知识库；
- 选择Obsidian、飞书或其他知识库工具；
- 诊断已有共享文件夹或在线知识库；
- 整理一批新增制度、SOP或产品资料；
- 处理一次错误回答、版本冲突或权限问题；
- 设计知识库周、月或季度运营机制。

第一次练习只选择一个主要任务。

---

## 二、开始前需要准备什么

| 项目 | 建议准备 |
|---|---|
| AI工具 | Codex或WorkBuddy |
| Skill | 团队AI知识库运营助理 |
| 真实场景 | 制度问答、新人培训、产品知识、客服、销售或项目案例等 |
| 资料 | 先提供一个文件夹或3～10份关键资料 |
| 真实问题 | 最好准备10～30个员工或客户真实问题 |
| 团队信息 | 使用人员、业务负责人和资料负责人 |
| 当前工具 | Obsidian、飞书、语雀、网盘、Wiki或其他平台 |
| 权限边界 | 明确敏感资料、不可上传内容和审批要求 |

可用资料包括：

- 正式制度和业务规范；
- 产品手册、SOP和培训材料；
- FAQ、客服工单和销售问题；
- 项目报告、复盘和案例；
- 会议纪要和工作总结；
- 老员工经验访谈；
- 现有知识库目录或资料清单。

> [!warning] 权限与安全
> 敏感资料进入外部AI前应先脱敏并确认授权。批量创建、移动、覆盖、归档、权限调整、正式知识修改和对外发布前必须确认。

## 三、安装和启动Skill

课程交付包中提供：

- `team-knowledge-operator/`：Skill主包；
- Codex安装与使用指南；
- WorkBuddy安装与使用指南；
- 通用AI工具使用指南；
- 首次建设、资料更新和质量治理示例。

安装后可使用以下启动指令：

```text
请以团队AI知识库运营助理的身份开始工作。

我希望解决的业务问题是：{填写问题；暂不确定可删除本行}
主要使用人员是：{填写用户；暂不确定可删除本行}
现有资料位置是：{填写文件夹或资料路径}
当前使用或考虑的工具是：{填写工具；不确定可写“请推荐”}

请先读取已有资料并进行只读分析，
主动判断最适合的首期场景、范围和建设方案。
先给出推荐理由和需要确认的事项，
未经确认不要批量创建、移动、覆盖或发布正式知识。
```

如果暂时只知道资料位置，可以只提供路径。助理会先分析资料，再提出少量必要问题。

## 四、练习一：判断是否适合建设知识库

### 作业目标

判断当前业务问题是否适合通过团队AI知识库解决，并选出首期场景。

### 使用的执行说明书

使用Skill中的适用性判断和触发路由规则。

### 启动方式

```text
我们的团队目前存在以下问题：
{描述重复咨询、资料难找、口径不一、新人培训或经验流失等问题}

请判断这些问题是否适合建设团队AI知识库。
请使用频率、业务价值、知识基础、标准程度、
可验证性、风险程度和使用意愿进行评估。

给出推荐首期场景、暂不建议建设的场景及理由。
```

### AI会怎样引导你

AI会分析业务问题、候选用户、已有知识基础、风险和可验证性，并推荐优先场景。

### 你需要重点确认

- 是否确实存在高频使用需求；
- 目标用户是否愿意改变当前工作方式；
- 是否已有可用资料或业务专家；
- 是否存在相对明确的答案或流程；
- AI输出是否能够人工验证；
- 错误回答的风险是否可控；
- 预期价值能否通过时间、成本或质量衡量。

### 预设成果

- 场景适用性评估；
- 推荐首期场景；
- 目标用户；
- 业务价值；
- 风险和资料缺口；
- 暂不纳入场景。

### 完成标准

- 已确定一个首期场景；
- 已明确主要用户；
- 已说明业务问题和预期价值；
- 已记录风险和验证方法；
- 已明确至少一项暂不纳入内容。

## 五、练习二：从零建设最小可用知识库

### 作业目标

围绕一个场景完成八步规划，形成首期知识库建设方案。

### 使用的执行说明书

使用Skill中的首次建设、治理规则、风险审批、知识结构和质量评测规则。

### 启动方式

```text
请基于当前场景和资料，按以下八步规划团队AI知识库：

1. 找场景；
2. 定边界；
3. 盘知识；
4. 治内容；
5. 选工具；
6. 建应用；
7. 做验证；
8. 持续进化。

每一步开始时说明目的和价值，
优先读取现有资料并主动给出推荐方案。
将需要我判断的问题集中列出。
先完成只读分析和建设方案，不直接修改正式资料。
```

### AI会怎样引导你

助理通常分阶段完成：

1. 场景与边界诊断；
2. 知识资产盘点与治理设计；
3. 工具选型与平台落地建议；
4. 知识结构、应用和测试设计；
5. 运行规则与持续运营设计。

### 你需要重点确认

- 首期服务对象和使用场景；
- 知识库回答什么、不回答什么；
- 哪些资料是权威来源；
- 存在冲突时由谁决定口径；
- 哪些内容属于敏感资料；
- 内容负责人和审核人；
- 使用哪一种知识库工具；
- 哪些行为必须转人工；
- 正式发布和旧版下线规则；
- 首期成功标准。

### 预设成果

- 知识库建设章程；
- 场景与用户定义；
- 首期范围及排除清单；
- 知识资产盘点表；
- 分类和元数据规则；
- 责任与权限矩阵；
- 工具选型建议；
- 知识库目录；
- 测试问题集；
- 更新维护机制。

### 完成标准

- 八个步骤均形成明确结论；
- 正式知识与原始资料分开；
- 权威来源、负责人和审核人明确；
- 工具选择有可解释依据；
- 已准备真实测试问题；
- 已建立反馈和更新闭环；
- 所有待确认和高风险事项已单独列出。

## 六、练习三：选择知识库工具

### 作业目标

根据业务场景、资料、协作和权限需求选择工具，并形成平台落地方案。

### 使用的执行说明书

使用Skill中的工具选型、平台落地及Obsidian、飞书或通用在线Wiki适配规则。

### 启动方式

```text
请根据我们的知识库目的、目标用户、资料类型、
协作方式、权限要求、AI应用和预算，
比较本地文件型、在线协作型和企业级知识库平台。

请至少从以下维度评估：
场景适配、资料适配、协作能力、权限安全、
AI能力、维护能力、系统集成和总体成本。

给出推荐工具、替代方案、能力缺口和落地步骤。
```

### AI会怎样引导你

AI会分析用户数量、资料格式、异地协作、移动访问、审批、权限、系统集成、IT能力和预算。

### 你需要重点确认

- 团队是否需要多人实时编辑；
- 是否需要评论、审核和通知；
- 是否要求本地存储；
- 是否有部门或文档级权限需求；
- 是否需要在线AI问答或业务系统调用；
- 资料是否大量使用Markdown、Office、PDF或多媒体；
- 当前团队已经使用什么办公平台；
- 是否有IT支持和持续维护预算。

### 预设成果

- 工具需求清单；
- 候选工具对比矩阵；
- 推荐方案；
- 能力缺口与补救措施；
- 知识结构映射；
- 迁移和实施计划。

### 完成标准

- 推荐工具与业务需求匹配；
- 明确唯一正式知识来源；
- 权限、版本和审核机制可以落地；
- 已说明不选择其他工具的理由；
- 已列出平台能力不足时的补救措施。

---

## 七、练习四：处理新增与变更资料

### 作业目标

将新资料安全地转化为候选知识，并分析对现有知识的影响。

### 使用的执行说明书

使用Skill中的知识更新和治理规则。

### 启动方式

```text
这些是本次新增或变更的资料：{资料位置}

请判断它们属于新增、补充、修订、替代、
纠错、失效、合并还是权限变更。

请分析关联的正式知识、旧版本、FAQ、模板、
案例、测试题和权限影响。

先生成更新草案和变更预览，
未经确认不要修改或发布正式知识。
```

### AI会怎样引导你

AI会登记新资料、判断变化类型、识别相关知识和版本、检查冲突与敏感信息，并生成更新建议。

### 你需要重点确认

- 新资料是否来自可信来源；
- 是否替代已有正式版本；
- 影响哪些FAQ、SOP、模板或案例；
- 是否改变适用对象和生效时间；
- 是否存在冲突口径；
- 是否涉及敏感信息和权限；
- 谁负责审核；
- 旧版本是保留、归档还是下线；
- 更新后需要重新测试哪些问题。

### 预设成果

- 新资料登记；
- 更新影响分析；
- 候选知识草案；
- 版本替代建议；
- 审批事项；
- 回归测试清单；
- 变更记录。

### 完成标准

- 新资料未直接覆盖正式知识；
- 已识别变化类型和影响范围；
- 冲突、权限和版本问题均已标记；
- 正式发布前存在明确审核步骤；
- 更新后安排了回归测试和留痕。

## 八、练习五：诊断或治理现有知识库

### 作业目标

分析已有知识库的场景、内容、结构、权限、运营和应用问题。

### 使用的执行说明书

使用Skill中的现有知识库诊断、质量治理和评测规则。

### 启动方式

```text
请对当前知识库进行只读诊断：{知识库位置}

从以下六个方面检查：
1. 场景价值；
2. 内容质量；
3. 结构与检索；
4. 版本与权限；
5. 运营与责任；
6. 应用与效果。

如果存在错误回答，请复现问题并定位根因。
先输出诊断报告和分级改造建议，不直接批量修改。
```

### AI会怎样引导你

AI会扫描知识结构，识别缺失、重复、版本、元数据、链接、权限和应用问题，并提出修复优先级。

### 你需要重点确认

- 当前知识库是否仍解决真实问题；
- 正式资料是否有效且有负责人；
- 是否存在多个权威版本；
- 错误来自资料、治理、结构、检索、回答规则还是权限；
- 哪些问题需要立即止损；
- 哪些知识可以局部修复；
- 是否需要结构重组或场景重构；
- 修复是否涉及正式知识和权限；
- 如何验证修复没有带来新问题。

### 预设成果

- 六维诊断报告；
- 问题分级清单；
- 根因分析；
- 改造建议；
- 变更预览；
- 回归测试方案。

### 完成标准

- 问题有证据和明确等级；
- 已区分症状与根因；
- 高风险事项优先处理；
- 修改正式知识前获得确认；
- 修复后测试原问题、变体问题和权限边界。

## 九、建立持续运营节奏

### 每周

- 处理新增资料；
- 处理待审核知识；
- 检查错误回答和未命中问题；
- 处理失效引用；
- 跟进超期任务和临近复核内容。

### 每月

- 分析使用情况；
- 检查有效回答率和引用质量；
- 识别知识缺口；
- 检查新增资料处理效率；
- 形成责任明确的优化任务。

### 每季度

- 重新评估场景和范围；
- 复核用户、责任人和权限；
- 清理历史版本和重复内容；
- 判断是否扩展新的知识库应用；
- 评估投入产出和业务价值。

推荐指令：

```text
请对本周期团队知识库进行运营复盘。

请分析：
- 使用情况；
- 回答质量；
- 知识覆盖；
- 新资料和变更处理；
- 权限与风险；
- 对业务效率和质量的影响。

将发现的问题转化为负责人明确、可以验收的优化任务。
```

## 十、每次任务结束都要做什么

要求助理按以下结构报告：

```markdown
## 本次采用的流程

## 分析的资料

## 核心判断与依据

## 用户已确认事项

## 创建或修改的文件

## 测试结果

## 未解决风险与下一步
```

正式写入前检查：

- 这是已确认事实还是AI建议；
- 是否有来源和版本；
- 是否明确适用范围；
- 是否包含敏感信息；
- 是否会覆盖现有正式知识；
- 是否需要业务负责人审核；
- 是否需要保留旧版本；
- 发布后是否安排测试。
