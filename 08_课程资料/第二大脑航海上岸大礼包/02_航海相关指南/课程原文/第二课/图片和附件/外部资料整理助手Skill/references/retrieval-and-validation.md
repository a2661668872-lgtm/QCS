# 检索与质量验证

## 查询理解

先判断用户在找：

- 工具；
- 场景或痛点；
- 方法或流程；
- 风险与检查项；
- 数据与证据；
- 来源；
- 所有符合条件的素材。

保留用户原始表达，再将口语映射为稳定概念。

## 词语关系

- 严格同义词：可双向扩展；
- 用户口语：映射到标准词；
- 上下位与相关概念：低权重按需扩展；
- 查询意图：转换为证据、风险、来源、时效等检索动作。

不得把相关但不等同的概念视为完全同义词。

## 三种检索路由

### 相似内容

```text
查询扩展
→ 关键词或语义召回
→ 元数据加权
→ 素材类型重排
```

### 条件筛选

例如“哪些需要复核”：

```text
直接筛选 timeliness 与 verification_status
→ 返回全部符合项
→ 按原因分组
```

不要固定只返回前几项。

### 组合资料包

```text
找到核心场景或问题
→ 补充工具与方法
→ 补充风险、数据和来源
→ 检查时效与验证状态
```

## 质量检查

- 目录结构是否通过唯一性与必需目录检查；
- 正式素材是否全部通过元数据检查，不能只验证带有 `material_id` 的子集；
- 核心素材是否被找到；
- 是否混入明显无关素材；
- 是否能追溯来源；
- 是否提示关键风险与时效；
- 是否能直接组合用于用户任务；
- 是否存在资料缺口。

验证报告必须区分精确数量与估算数量。能够从台账计算时不得使用“约”“~”替代。

## 验证测试

每个知识库维护一组真实用户问题，覆盖用户可能使用的自然语言，而不只使用素材库内部术语。

规则、元数据或资料更新后重新运行相关测试。高召回不等于高精确率，仍需检查排序与误召回。

## 两级验证

### 检索验证

使用用户自然语言问题，确认能够找到正确的原子素材、来源和限制。

### 应用验证

选择一个真实任务，将其拆为素材需求，实际生成成果草案并检查：

- 是否能组合出完整结果；
- 是否过度依赖重新阅读源资料；
- 是否缺少关键知识类型；
- 是否有无法追溯或已经过时的内容；
- 用户是否认为结果可用。

只完成检索验证，可以声明“知识库初始化完成”；完成真实任务并记录结果后，才能声明“知识库应用验证完成”。

应用结果为部分成功时，只能声明“知识库应用部分验证完成”。用户明确确认知识库和应用成果可投入使用后，才能声明“知识库正式交付完成”。
