# 工作流与路由

## 总流程

```text
找到资料
→ 轻量识别
→ 明确目的或推荐方向
→ 设计知识库提炼蓝图
→ 动态评估与批次选择
→ 建立完整任务计划并获得用户确认
→ 初始化并验证知识库目录结构
→ 按载体整理
→ 建立台账、综合卡、原子素材与索引
→ 验证检索效果
→ 运行真实应用任务
→ 完成验收与交付
```

## 资料入口路由

### 已确定范围

适用于用户指定文件夹、文件或链接。直接轻量扫描并形成识别清单。

### 未确定范围

适用于用户不知道资料位置。先扫描用户确认的范围，只读取元信息，输出候选目录和主题分布，再推荐深读范围。

### 外部大型知识库

先建立入口认知、目录与链接队列，再按目的筛选页面。不得直接承诺全部抓取。

## 动态价值评估

评估维度由用户目的决定，常用问题包括：

- 是否直接帮助当前任务；
- 是否能支持多个未来任务；
- 是否提供当前资料库缺少的信息；
- 来源与证据是否可信；
- 多久会过时；
- 解析和验证成本是否值得；
- 是否涉及版权、隐私或专业风险。

将资料分为：

- 现在深挖；
- 轻量整理；
- 待验证；
- 暂不处理。

## 处理深度与预算

为每份资料指定处理深度：

- `L1 快速识别`：仅建立识别记录、主题和潜在价值；
- `L2 标准整理`：生成源资料综合卡并提炼少量高价值原子素材；
- `L3 深度提炼`：对高价值资料建立结构地图并完整拆解。

执行方案必须定义：

- 本轮 L3 和 L2 的最大资料数量；
- 单份资料建议及最大原子素材数；
- 最大总素材数或时间预算；
- 达到主题覆盖目标、边际新增价值过低或重复率过高时的停止条件。

默认先小批量验证模板与质量，再扩大处理。不得为每个资料类型机械创建大量子任务。

## 整理方案必须包含

1. 当前目的与默认假设；
2. 知识库提炼蓝图与未来调用任务；
3. 本轮资料范围和选择原因；
4. 每类载体的处理方法；
5. 综合卡与原子素材的提炼规则；
6. 调用入口、检索与应用验证方法；
7. 预计成果与保存位置；
8. 未处理范围；
9. 完成门槛；
10. 需要用户确认的事项。
11. 目录初始化方案、处理预算与停止条件。

## 完整任务计划门槛

开始批量整理前，任务计划至少包含：

1. 保存整理目的与执行边界；
2. 保存提炼蓝图；
3. 建立资料识别清单与处理台账；
4. 初始化并验证知识库结构；
5. 生成必要的源资料综合卡；
6. 按蓝图提炼原子素材；
7. 建立来源关系与调用入口；
8. 执行真实问题检索验证；
9. 推荐并执行一个应用验证任务；
10. 生成覆盖报告与完成清单；
11. 运行完成验收。

缺少任一项时先补全计划，不得把任务收缩为“生成素材卡和索引”。

## 子代理继承规则

派发子代理任务时必须附带：

- 用户目的与目标使用场景；
- 本轮资料范围；
- 提炼蓝图中适用的素材类型和字段；
- 综合卡与原子素材的区分；
- 来源、时效与验证要求；
- 输出位置与命名规则；
- 子任务完成标准。

子代理只完成局部处理，主代理仍负责跨资料去重、关系索引、检索验证、应用验证和最终验收。

## 阶段产出边界

| 阶段 | 允许生成的核心成果 |
|---|---|
| 找资料与目的 | 识别清单、目的草案 |
| 蓝图与方案 | 提炼蓝图、执行方案、目录蓝图 |
| 初始化 | 正式目录、基础说明、结构验证报告 |
| 自动整理 | 台账、综合卡、原子素材、来源关系 |
| 检查验证 | 检索报告、覆盖报告、缺口报告 |
| 成果激活 | 用户确认的一个应用成果及应用验证报告 |
| 完成交付 | 完成清单、验证报告、交接报告 |

生成超出当前阶段的成果前，必须获得用户对相应应用任务的确认。

## 中断与恢复

长任务应保存：

- 已发现资料；
- 已处理状态；
- 失败原因；
- 已生成成果；
- 下一步队列。

再次执行时从未完成条目继续，不重复处理已完成且指纹未变化的资料。
