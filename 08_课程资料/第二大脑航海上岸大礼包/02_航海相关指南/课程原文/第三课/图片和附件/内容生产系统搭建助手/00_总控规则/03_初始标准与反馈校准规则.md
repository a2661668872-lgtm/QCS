# 候选标准、真实验证与反馈校准规则

## 核心原则

标准用于保证质量，规则用于适应用户。规则必须经过真实使用逐步形成，不能在首次共识或一次试跑后批量生效。

## 规则状态

| 状态 | 使用方式 |
|---|---|
| 内置质量底线 | 相关任务必须检查 |
| AI建议 | AI基于资料与方法提出，尚未获得用户认可 |
| 候选规则 | 值得试用，但尚未确认 |
| 用户确认可试用 | 后续任务可以应用，仍需验证 |
| 单次验证 | 在一次真实任务中有效 |
| 多次验证 | 可作为稳定规则 |
| 已废弃 | 不再使用，保留原因 |

## 强制限制

- 一次用户确认不得直接升级为稳定规则；
- 一次真实任务不得批量产生多条稳定规则；
- AI自检通过不等于规则有效；
- 用户尚未体验的标题、风格、排版、封面等标准不得提前固化；
- 产品功能、工具路径、政策、平台规则和其他易变化事实默认需要时效核验；
- 用户提出“不需时效验证”时，AI必须说明风险并保留事实核验底线。

## 校准方式

试跑后先拆解成果要素，由AI推荐最需要校准的一项。一次只校准一个关键要素，其他问题进入待校准清单。
