# 第三课快速学习手册

> [!summary] 这节课的核心
> 内容生产系统不是让AI临时写一篇内容，而是连接已有知识资产，为AI建立一套包含流程、方法、工具和规范，并能通过真实任务持续校准的重复生产系统。

## 二、这节课在整套课程中的位置

课程前半部分搭建的是基础素材知识库，后半部分进入知识库应用场景。

| 课程阶段 | 产出 | 主要作用 |
|---|---|---|
| 创建AI助理 | 个人认知报告 | 让AI认识用户、偏好和背景 |
| 个人经验知识库 | 个人知识树、经验方法 | 调用用户自己的经验 |
| 学习研究知识库 | 外部资料内容素材 | 调用外部观点、案例、工具和数据 |
| 内容生产系统 | 流程、方法、工具、规范 | 持续完成一类内容生产任务 |
| 后续应用 | 项目管理、业务经验沉淀 | 将知识资产用于更复杂工作 |

> [!important] 核心变化
> 前两课解决“AI可以调用什么资料”，第三课解决“AI如何使用这些资料，稳定完成一类重复工作”。

## 三、为什么AI能批量写内容，却不一定有效果

AI能够快速生成文章、汇报、短视频脚本和小红书图文，但结果不一定能产生业务价值。常见原因包括：

- AI不了解真实业务、目标人群和内容目标；
- 用户只给了任务，没有给有效方法；
- 有生产步骤，但没有判断标准；
- 每次反馈和修改没有沉淀；
- AI只能重复生成，不能持续改进。

当用户本身不擅长选题、写作或运营时，完全依赖AI自主规划，通常只能得到“看起来正确”的普通结果。

想让AI更有确定性地重复执行，需要给它四类信息：

```text
流程 + 方法 + 工具 + 规范
```

| 组成部分 | 解决的问题 | 小红书示例 |
|---|---|---|
| 流程 | 先做什么，后做什么 | 采集爆款 → 策划选题 → 写作 → 配图 → 发布 → 复盘 |
| 方法 | 每一步怎样做 | 如何寻找关键词、怎样拆解爆款 |
| 工具 | 使用什么完成 | 浏览器、数据工具、AI生图工具 |
| 规范 | 怎样才算做好 | 爆款定义、选题标准、标题标准、视觉标准 |

只有流程，没有方法、工具和规范，只是一张步骤图，不是一套可稳定运行的系统。

## 四、什么是内容生产系统

内容生产系统是一套围绕特定内容任务建立的重复工作系统。它能够：

1. 连接用户已有的个人经验与外部资料；
2. 明确内容目标、目标人群和策略；
3. 规划完整生产流程；
4. 为各流程环节建立方法与规范；
5. 调用适合的工具完成任务；
6. 使用真实任务验证；
7. 根据反馈和数据持续更新。

### 内容知识库主要保存什么

内容生产系统的知识库不是为了再次保存所有原始资料，而是重点保存：

- 系统目标、定位与策略；
- 内容生产流程；
- 选题、写作、排版和视觉等规范；
- 素材调用关系；
- 已完成的内容成果；
- 用户反馈、问题和修正记录；
- 经过多次验证的稳定规则。

原始经验和外部资料仍保存在前两课搭建的基础素材知识库中，通过索引和调用关系连接。

## 五、应该搭建哪一种内容生产系统

课程工具包主要支持两类场景。

### 5.1 工作写作内容

- 日报、周报、月报；
- 阶段总结和工作计划；
- 客户方案；
- 汇报材料；
- 述职、晋升和年度总结；
- 其他周期重复提交的材料。

### 5.2 公开发表内容

- 公众号文章；
- 小红书图文；
- 短视频脚本；
- 专业主题知识库；
- 其他需要持续更新的公开内容。

### 5.3 如何划分系统边界

一套系统通常服务一类具有相似流程和规范的内容，不应试图覆盖所有写作任务。

| 可以放在同一系统 | 不建议放在同一系统 |
|---|---|
| 日报、周报、月报 | 周报与年度战略规划 |
| 同一公众号的不同文章栏目 | 公众号文章与客户方案 |
| 同一产品的不同客户方案 | 客户方案与述职报告 |
| 年度总结、述职、晋升材料 | 小红书图文与正式汇报材料 |

如果不确定哪些任务可以归类，可以让AI根据流程和规范相似度提供建议。

## 六、内容生产系统搭建的完整流程

```text
确认资料位置与授权边界
→ AI扫描资料并推荐优先系统
→ 用户确认系统方向
→ AI诊断并优化内容策略
→ 规划完整生产流程并连接素材
→ 推荐首个建设环节
→ 一次建设一个流程环节
→ 使用真实任务试跑
→ 用户反馈与成果校准
→ 将验证后的方法和规范沉淀进系统
→ 进入日常运行并持续升级
```

### AI与用户分别负责什么

| AI主要负责 | 用户主要负责 |
|---|---|
| 扫描资料并提出候选方向 | 确认授权范围和系统方向 |
| 诊断定位并提出策略建议 | 判断建议是否符合真实目标 |
| 规划流程、方法和候选规范 | 确认关键决定 |
| 调用素材并完成真实任务 | 检查准确性和效果 |
| 拆解问题并提出修正建议 | 提供具体反馈 |
| 更新候选规则和系统记录 | 决定是否继续验证或固化 |

> [!important] 协作原则
> 一次看清完整流程，一次只建设一个环节；每轮只确认一个关键决定。

## 七、如何让系统越用越聪明

第一次搭建出来的系统通常只是0.5版或1.0版。很多规范只有在真实使用后才能被发现和校准。

### 规则升级路径

```text
AI建议
→ 候选规则
→ 用户确认试用
→ 真实任务验证
→ 根据反馈修改
→ 多次验证
→ 稳定规则
```

可以用于校准系统的反馈包括：

- 用户对文章、方案或汇报的修改意见；
- 老板、客户、同事对工作内容的反馈；
- 发布后的阅读、搜索、转发和咨询数据；
- 实际排版、发布和使用中发现的问题；
- 用户提供的优秀参考样本。

反馈必须具体。例如，不要只说“写得不好”，而应说明：

- 哪一部分不符合预期；
- 为什么不合适；
- 希望修改成什么方向；
- 这个修改是否应该成为长期规范。

## 八、课堂演示中的关键经验

### 8.1 AI推荐的方向不一定要接受

AI会根据已有资料推荐系统方向。用户可以接受，也可以直接告诉AI自己真正想做的主题。

### 8.2 历史资料越丰富，搭建越快

如果知识库中已经有选题标准、历史文章、写作风格和排版规范，AI可以直接复用并适配新系统，减少重复确认。

### 8.3 不知道成果保存在哪里，直接问AI

如果AI已经生成规范或成果，但用户不知道保存位置，可以直接询问，并要求后续统一保存到指定文件夹。

### 8.4 把AI当助理，不要当固定程序

Skill提供的是推荐流程，不代表用户不能打断。方向跑偏、位置不对、结果不满意或不知道下一步时，都可以直接告诉AI。

### 8.5 内部编号通常不用理解

AI生成的M01、S02等编号主要供系统内部管理。用户只需要理解当前要确认的事项和实际成果。

## 九、常见误区

| 常见误区 | 正确做法 |
|---|---|
| 内容生产系统就是让AI写文章 | 先建立目标、流程、方法和规范，再通过真实任务验证 |
| 一套系统可以写所有内容 | 选择流程和规范相似的一类内容 |
| 一开始就要确定全部标准 | 一次建设一个环节，在真实任务中逐步校准 |
| AI推荐什么就必须做什么 | 将真实目标告诉AI，要求它重新规划 |
| 一次试跑满意就形成稳定规范 | 多次验证后再固化 |
| 修改结果就结束任务 | 要求AI将有效修改更新到系统规范 |
| 不知道下一步就停止 | 直接询问“下一步应该做什么” |
