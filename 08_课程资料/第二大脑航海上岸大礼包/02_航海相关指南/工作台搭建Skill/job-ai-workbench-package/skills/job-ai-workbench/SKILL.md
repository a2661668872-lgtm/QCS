# 岗位AI工作台搭建

## 首次使用先说明

如果库内没有 `00_使用说明.md` 和 `01_岗位档案/岗位工作地图.md`，视为首次使用。

首次触发先告诉用户：

```text
这是“岗位AI工作台搭建”Skill。

它会根据你的岗位和你上传的真实资料，整理岗位资料、工作对象、规则和审核标准，再找出3条最值得后续做成AI Skill的工作流。

不同岗位得到的内容不同：财务会得到财务工作台，采购会得到采购工作台，销售、人事、市场、客服和管理岗位也会按各自资料动态生成。

第一次请先把现有岗位资料放进当前知识库。我会完整读取资料，资料里已经有的信息不再重复问，只补影响搭建的关键缺口。

本次只搭工作台和识别候选工作流，不包含每周巡检、定时任务、完整Skill或Agent连接。
```

如果用户还没有上传资料，告诉他最少放入以下任意2类，然后等待资料：

1. 岗位职责、部门目标或日常工作清单。
2. 制度、SOP、表格、模板或历史合格结果。
3. 会议纪要、聊天记录、常见问题或异常案例。

如果用户已经提供资料或资料就在当前库中，直接读取，不再要求重新上传。

## 最终交付

首次搭建完成后必须交付：

1. 岗位工作地图。
2. 已有资料清单和资料源地图。
3. 与岗位匹配的对象资料和协作关系。
4. 岗位判断规则、人工审核点和敏感边界。
5. 3条候选AI工作流，标明输入、动作、输出、人工审核和价值。
6. 最推荐先做的一条及理由。
7. 只包含真实缺口的待补资料清单。
8. 岗位版 `AGENTS.md` 和使用说明。

## 必读资源

首次搭建时完整读取：

- `references/job-routing.md`
- `references/gap-questions.md`
- `references/job-agents-template.md`
- `references/output-templates.md`

## 执行流程

### 第0步：确认资料状态

1. 确认当前目录是用户要使用的 Obsidian 库。
2. 扫描当前库和用户明确提供的文件。
3. 找到岗位资料后直接进入阅读；不要先抛出采访问卷。
4. 没有任何岗位资料时，才请用户先上传最少2类资料。
5. 已有成熟目录时沿用原结构，不覆盖、不批量移动。

### 第1步：完整阅读资料

先读后问。不能只看文件名或AI摘要代替原文。

阅读后输出内部工作清单：

- 已经确认的岗位、职责、对象、输入、输出、规则和常见问题。
- 每项信息的来源文件。
- 前后矛盾、过期内容和敏感事项。
- 真正影响工作台搭建的缺口。

资料中已经写明的内容禁止重复询问。

### 第2步：识别岗位和搭建范围

按 `references/job-routing.md` 判断主岗位。一个人兼任多个岗位时：

- 选择与当前目标最相关的岗位作为主线。
- 其他岗位作为协作模块，不建立多套重复工作台。
- 资料足够时直接判断；无法判断时只问“这次最想先搭哪个岗位”。

搭建范围默认是“当前使用者的岗位”，不是一次搭整家公司。

### 第3步：只补关键缺口

按 `references/gap-questions.md` 选择性追问。

最多补问5个关键问题。能从资料推断但没有证据的内容标【待补】，不要为了填满模板连续采访。

关键缺口仅指会影响以下事项的信息：

- 不知道岗位最终要交付什么。
- 不知道关键工作对象是谁。
- 不知道什么算合格结果。
- 不知道谁负责审核或拍板。
- 不知道哪类资料敏感或不能交给AI。

### 第4步：生成岗位专属工作台

新库默认创建：

```text
00_上传资料/
01_岗位档案/
02_岗位资料库/
03_对象与协作方/
04_工作流程/
05_规则与审核标准/
06_AI输出区/
skills/
```

目录骨架相同，具体文件名和内容必须按岗位生成。参考 `references/job-routing.md`，禁止给所有岗位复制同一套空模板。

创建：

```text
00_使用说明.md
01_岗位档案/岗位工作地图.md
01_岗位档案/资料源地图.md
04_工作流程/候选AI工作流.md
05_规则与审核标准/判断标准与人工审核.md
05_规则与审核标准/敏感信息与使用边界.md
AGENTS.md
```

并按岗位动态补充文件。例如：

- 财务：费用制度与报销规则、账务资料索引、常见异常。
- 采购：供应商与品类、询价比价规则、采购审批边界。
- 销售：客户与线索、跟进阶段、异议与成交资料。
- 人事：岗位与候选人、面试标准、入转调离资料。

使用 `references/output-templates.md`。没有资料的字段标【待补】，不编造。

### 第5步：识别3条候选工作流

从真实资料中找高频、重复、规则相对明确、资料可得、风险可控的工作。

每条候选写清：

```text
工作流名称
当前触发场景
输入资料
主要步骤
关键判断
人工审核点
输出
为什么值得做
资料是否足够
```

候选排序标准：

1. 每周反复发生。
2. 当前耗时或返工明显。
3. 有真实输入和合格样例。
4. AI能辅助，但不会替代重大决策。
5. 后续可以在课程中做成一个独立Skill。

最终推荐1条优先流程，但本次不继续生成该流程的完整Skill。

### 第6步：生成岗位版 AGENTS.md

读取 `references/job-agents-template.md`，写清：

- 使用者岗位和当前重点。
- 资料来源与目录规则。
- 关键对象和协作人。
- 输出标准、人工审核和敏感边界。
- 候选工作流及后续可调用Skill位置。

已有 `AGENTS.md` 时不覆盖，只做兼容性追加；冲突内容标待确认。

### 第7步：完成验收

检查：

- 是否完整读取了已有资料。
- 是否避免重复询问。
- 是否生成岗位专属而非通用空模板。
- 是否有来源、规则、人工审核和敏感边界。
- 是否给出3条候选工作流并推荐1条。
- 是否只列真实缺失资料。

最终一屏汇报：

```text
你上传了什么资料
AI已经了解了什么
生成了哪些岗位资产
识别出哪3条候选工作流
最建议先做哪一条
还缺哪些关键资料
```

## 后续补充资料

用户说 `补充岗位资料` 或 `整理岗位资料` 时：

1. 完整读取新增资料。
2. 更新已有岗位档案、对象资料、规则和候选工作流。
3. 同主题优先追加旧文件，不重复建档。
4. 不执行每周巡检，不创建定时任务。

## 红线

1. 不删除或改写原始资料。
2. 不覆盖已有目录、AGENTS或负责人结论。
3. 不重复询问资料中已经明确的信息。
4. 不把AI推断当成岗位事实。
5. 不暴露密码、API Key、身份证、银行卡或未脱敏隐私。
6. 不替人审批、付款、签约、录用、解雇或对外发布。
7. 不在本次搭建每周巡检、定时任务、完整Skill或Agent。
