# QCS 爆款对标结构拆解与多稿件迁移设计

## 目标与范围

让 QCS 在做单条选题、设计结构和写初稿时，先利用一条相关的爆款对标视频理解整条内容怎样推进，再从其他相关稿件中寻找可服务当前段落的材料与表达思路，最终用用户自己的真实材料完成一条连贯的稿子。重点是具体作品的推进顺序与信息释放，不是套用一个通用爆款公式，也不是替换原稿中的名词和数字。

本次只改现有 QCS 与写稿流程，不新建子 Skill、对标数据库或第二套稿件。用户只要诊断或候选时不写文件；用户授权保存时，优先写入现有单条编导卡和现有写稿产物。

## 触发与素材选择

- 用户指定对标视频时优先使用指定作品。没有指定但正在做选题或结构、且 `02_内容素材/` 有明显相关作品时，可定向选一条；不整库加载，也不为了形式强找对标。
- 选对标看目标观众、内容任务、表现形式和可用材料是否相近，不只看播放数字。播放、点赞等只作有时间与口径的观察，不据此断言某种结构导致爆款。
- 使用用户给出的正文、已有素材笔记和可读取的原视频信息。只有文字稿时只拆**文字和信息结构**；没有画面证据不描述镜头、剪辑或表情。
- 素材库正式来源继续遵守现有有效内容条件及辅助文件排除规则。原视频、素材路径与二次分析分开记录；来源缺失时标为线索，不冒充核实。

## 单条对标拆解

不预设固定的三段式或固定段数，按作品实际转折逐段记录：

| 字段 | 要回答的问题 |
| --- | --- |
| 顺序与可定位片段 | 这一段在视频的什么位置、说了或展示了什么（简述，不大段摘抄）？ |
| 内容任务 | 它是定题、承诺、提前兑现、举证、解释、制造新问题、处理顾虑，还是促成反馈？ |
| 观众状态 | 观众在这里已知道什么、还想知道什么，为什么有理由继续看？ |
| 依赖材料 | 这一段依靠什么真实事实、案例、演示或画面成立？ |
| 可迁移与不可迁移 | 哪个是可借鉴的段落功能；哪个依赖原作者身份、经历、数字、原句或素材，不能直接搬？ |

拆解只描述**观察到的安排**。对“为什么有效”的解释写成假设；没有留存、来源和可比样本，不升级成账号规律。

## 主对标与辅助稿件的分工

- **主对标**提供整条观看路径：开头承诺、首次兑现、主体如何递进、证据何时出现、结尾怎样回收。它是可调整的骨架，不要求逐段一一对应。
- **辅助稿件**提供局部候选：开头的切入方式、某段的观点、信息点、案例、金句的思想或修辞作用，以及结尾与 CTA 的任务。优先从用户指定材料、`02_内容素材/` 中的相关笔记和 `05_内容草稿/` 中用户自己的已确认稿件定向检索；不默认整库扫描。
- 先看这些片段是否解决本条观众此刻的问题，再看它能否接在主线上；不能只因一句话精彩就插入。一个功能已由当前材料完成时，不重复塞入另一个来源的同类段落。
- 每个采用的辅助片段记录：具体路径或链接、来源属于用户自己的稿件还是外部稿件、它在原稿中的作用、可迁移的信息或表达任务、本条准备用什么真实材料实现、采用或舍弃的理由。

外部稿件中的原句只能作为有来源的内部摘录来分析；写入初稿时使用符合用户立场和语言的改写，不把外部作者的句子或经历当成用户原创。用户自己已确认的旧稿句子可以在事实与本条语境仍成立时原样复用。CTA 只能指向当前内容真实可承接的评论、关注、尝试或下一步，不照搬别人的福利、产品或引流承诺。

## 迁移到当前选题或脚本

将主对标结构与当前内容做一张简短映射：`对标段落功能 → 本条观众问题 → 用户已有的事实/案例/观点 → 辅助稿件的相关片段及作用 → 本条具体表达任务 → 保留、换序或舍弃理由`。每个关键节点都必须能找到自己的材料；找不到时标记缺口、删掉该节点或换一种推进关系，不用虚构经历和结果补齐。

借鉴的是开头承诺何时兑现、信息怎样递进、案例如何支持观点、结尾如何回收等**功能关系**；不照搬外部来源的标题、开头句、原话、个人叙事腔调或整段正文。用户确认要原样保留的自己稿件优先。结构不适合本条主旨或目标观众时，可以不采用，并说明原因。

## 现有 Skill 分工与交接

- `qcs-topic`：在单条选题检索中识别一条有用的结构对标，并列出少量可能补强本题的其他稿件路径、相关性和内容角色；不提前拼正文。
- `qcs-structure`：用户要拆对标或设计整条观看结构时，完成主对标逐段功能拆解和迁移映射；辅助稿件只用于补足局部节点，继续检查首次兑现、持续观看理由与反馈点。材料不足时只返回可观察结构与缺口。
- `qcs-outline`：继承已选主对标及辅助稿件，按自己的主旨取舍，标明各片段服务哪个节点；不重复扫描素材库，也不被对标的段落数绑住。
- `shengcai-content-writer`：素材包关卡仍先收集材料、访谈、等待确认；把已选主对标与辅助片段的路径、来源身份和拟用位置放进现有素材包。初稿阶段若已有当前单条编导卡中的迁移映射，可将其作为**本条结构参考**，并只采用已核实、能衔接的辅助片段；不把它冒充 `03_内容规律` 的“本期可用”通用规律，也不覆盖用户确认的素材包或正文。
- QCS 总路由与共享契约：明确“找哪个对标”与“拆已定对标结构”不是同一任务。前者可进入现有对标筛选能力；后者进入 `qcs-structure`。一次只处理当前主任务，不自动连跑选题、拆解和写稿。

迁移结果默认在对话中交付。用户要求保存且已有对应编导卡时，写入其结构字段下的“对标结构参考”；只有对标、尚无本条选题时，不为这段拆解另建平行结构库。单条对标拆解不自动改写 `03_内容规律` 或 `当前导演规则`；规律提炼与升级仍走各自现有流程。

## 验证与完成标准

1. 增加路由/行为测试：明确指定对标时能拆出逐段功能；只要选题时不直接生成全文；没有合适对标时正常继续；只有文字稿时不编画面；对标结构缺少用户材料时不虚构填空。
2. 运行 `skills/qcs/scripts/validate-workspace.ps1`，对改动的 Skill 运行 `quick_validate.py`，检查引用与 Git diff。
3. 用一个已有 `02_内容素材` 主对标和至少一份相关辅助稿件做只读试跑：能区分主线、局部片段与本条可用事实；能交代辅助片段为什么放在该节点，不把多篇稿件机械拼接，也不把爆款表现写成结构因果。
4. 只提交本次 Skill 及必要测试、设计说明；保留已有用户改动，按 `AGENTS.md` 在验证后安全推送 Gitee `master` 并核对远端提交。

完成时，QCS 可以从一条具体爆款提炼可迁移主线，从其他相关稿件选择适用的开头、观点、信息点、金句思路、结尾或 CTA 功能，解释每个片段如何服务本条主旨，并让后续初稿使用这份有来源的映射；没有来源或本条材料时会明确降级，不机械拼贴。
