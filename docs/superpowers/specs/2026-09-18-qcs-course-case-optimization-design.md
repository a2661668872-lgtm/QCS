# QCS 课程案例驱动优化设计

## 目标与范围

让 QCS 在用户现有的 AI 生意与短视频创作任务中，更准确地判断结构、证据和画面，而不是增加一套行业模板。课程课件提供可迁移的编导方法；《100+行业爆款深度分析》提供测试这些方法的案例，不作为已验证的平台规律或可直接发布的事实来源。

本轮只改现有 QCS 契约、结构与画面子 Skill，以及评测场景。不新建行业子 Skill，不把整份大型 DOCX 复制进 Vault 或仓库，不改用户稿件、素材库、导演规则或其他 Skill。

## 已确认的方案

选择定向增强，而非只增参考索引或按行业继续拆 Skill。现有 QCS 已有定位、选题、结构、情境、故事、画面等职责边界；新增行业路由会使相同方法重复维护。只做索引则难以改变实际输出。

### 1. 课程案例的来源边界

在 `skills/qcs/references/shared-contract.md` 增加简短规则：

- 案例中的视频链接、可见画面、截图数据与作者的分析结论分开记录。
- 作者对“为什么爆”的解释只作为诊断假设；未经原视频、数据及适用条件核对，不升级为因果规则。
- 使用课程案例时只借鉴问题、信息关系和画面任务，不照搬标题、开头、原句或叙事腔调。
- 不自动读取外部 300 MB DOCX；用户指定案例或当前任务确需对照时，才定向读取相关条目。Skill 必须能在没有该本地文件的环境中正常工作。

这只是现有来源层级的补充，不建立第二套案例库或事实系统。

### 2. 结构判断更具体

在 `skills/qcs-structure/SKILL.md` 的既有流程中补充两项检查：

- 把开头承诺对应到正文中第一次有实质内容的兑现点。若结果、证据或方法出现过晚，优先考虑前移一项已有材料，不机械重写用户确认的开头，也不设置固定秒数阈值。
- 从现有材料选择合适的推进关系，例如因果、对照、递进或过程变化；每个主要节点必须改变观众对问题的理解，而非把若干“干货点”平铺。推进关系是候选，不是强制模板。

输出仍是当前的结构地图，不新增表格或完整写稿流程。只修改整条结构时生效；“只改开头”和“逐字稿衔接”继续分别交给 DBS 专项。

### 3. 纯口播加素材插入的轻量画面模式

在 `skills/qcs-visual/SKILL.md` 增加一个按需选择的模式：当用户已确定纯口播、仅需插入录屏、截图、产品画面或来源材料时，优先输出简表“口播节点—插入素材—它证明或解释什么—来源与缺口”。只选择确实承担证明、展示、解释或情境任务的素材；没有素材时保留占位，不编造画面。

用户要求完整分镜、景别、空间或导演风格时，仍使用现有详细镜头表。轻量模式不改确认稿，不因素材不足追加虚假结果，也不把素材插入点伪装成最终可用的媒体文件。

### 4. 以案例为原型的评测

在 `skills/qcs/evals/evals.json` 增加少量自包含场景，不依赖外部 DOCX 路径或长篇原文。重点覆盖：

1. AI 工具教程：结果和操作画面已存在，检查是否及时兑现开头、是否保留可理解的步骤。
2. 较长的抽象知识讲解：检查是否依据内容选择推进方式，而非强制压缩成某个时长或套用“三步公式”。
3. 课程作者将高互动归因于某个钩子、但只提供截图：检查 QCS 是否把分析标为假设，不当作已验证事实。
4. 用户正文已确认、拍摄形式为纯口播加素材插入：检查是否给出轻量画面方案，且不重写正文。

评测记录实际输入、预期边界和可观察行为，不通过固定措辞或标题匹配假装验证质量。

## 实施顺序与验证

1. 只编辑上述三个 Markdown 文件和一个 JSON 文件；先核对现有规则，避免重复表述。
2. 对改动的 Skill 运行 `quick_validate.py`，并运行 `skills/qcs/scripts/validate-workspace.ps1`；解析评测 JSON，检查新增 ID 唯一且原有场景保留。
3. 用代表性请求手工核对结构、来源边界和轻量画面输出；没有真实运行过的行为测试不得报告为已通过。
4. 查看最终 diff，排除无关的 `.obsidian/workspace.json` 与外部课程原件；检查敏感信息，仅提交本轮 Skill 改动。按项目规则非强制推送到 Gitee `master`，并核对远端提交。

## 完成标准

- 原有 QCS 路由、确认稿保护和事实边界不回退。
- 结构诊断能够指出承诺首次兑现的位置与主要推进关系，不把课程案例写成公式。
- 纯口播任务能得到可执行的素材插入清单；完整分镜任务仍得到详细镜头表。
- 新评测覆盖来源误判、结构套用和视觉过度设计三个真实风险。
- 验证结果与 Gitee 同步状态均如实报告；同步失败时不宣称已完成上传。
