# QCS 模块化 Skill 体系升级设计

## 1. 目标

把当前偏单体工作流的 `qcs` 改造成短视频编导总路由，并将安先生课程中已经结构化、可以独立执行和验收的方法，整理为 10 个能力型 `qcs-*` 子 Skill。

升级后的使用体验应是：用户只需要调用 `$qcs` 或直接描述当前问题；QCS 读取已有上下文，判断当前真正卡点，只调用一个最合适的子 Skill。用户也可以显式调用任一子 Skill。

本轮不把 38 节 5.0 课程逐课制成 38 个 Skill。课程文件是知识来源，Skill 是可执行能力；二者通过课程映射表连接。

## 2. 当前问题

现有 `skills/qcs/SKILL.md` 同时承担：

- 阶段识别与总控；
- 定位、选题、证据、大纲、结构和画面判断；
- 写稿、DBS、预测、发布与复盘路由；
- 课程读取、校音边界和规则升级。

这导致三个问题：

1. 每次调用都容易加载与当前卡点无关的方法。
2. 课程方法被压缩在一份 `course-methods.md` 中，具体能力无法独立调用和测试。
3. 总控与专业方法混在一起，后续新增课程时容易继续膨胀。

安先生课程已经明确采用“按问题调用”的学习方式：选题弱回选题课、理解困难回逻辑或情境课、画面空洞回影像课。因此 QCS 应采用动态路由，而不是默认完整串行执行全部课程步骤。

## 3. 已确认的设计决策

### 3.1 主入口只负责路由和衔接

`qcs` 负责：

- 读取当前对话，复用用户已经提供的信息；
- 识别当前内容阶段与一个最主要卡点；
- 选择一个 `qcs-*` 子 Skill 或已有外部 Skill；
- 传递完成该任务所需的最小上下文；
- 保证所有产物写入现有单条编导卡和现有内容目录；
- 用户没有明确下一步时，根据最新结果重新判断，而不是预设固定长链。

`qcs` 不再内嵌十种专业方法的完整流程。

### 3.2 按可执行能力拆分，不按课程文件拆分

一个课题只有满足以下条件，才独立成为子 Skill：

- 有明确的用户触发情境；
- 输入和输出可以说清楚；
- 完成结果可以验收；
- 与其他 Skill 的职责边界清楚；
- 已有结构化、注明边界的课程方法支持。

课程总览、学习地图、案例库、提示词模板、未经完整校音的原始逐字稿，不独立成为 Skill。

### 3.3 只有一个文件系统和一套内容产物

所有子 Skill 继续使用：

- `07_AI编导系统/单条编导卡/`；
- `04_选题库/`；
- `05_内容草稿/`；
- `06_发布复盘/`；
- `07_AI编导系统/实验假设池.md`；
- `07_AI编导系统/当前导演规则.md`。

不得创建第二套编导卡、素材包、稿件、预测、复盘、受众画像或规则库。

## 4. 总体架构

```text
用户请求
   |
   v
qcs：读取上下文 -> 判断阶段 -> 找到一个主要卡点
   |
   +-- qcs-positioning
   +-- qcs-topic
   +-- qcs-outline
   +-- qcs-viewer-path
   +-- qcs-structure
   +-- qcs-language
   +-- qcs-situation
   +-- qcs-story
   +-- qcs-visual
   +-- qcs-conversion
   |
   +-- shengcai-*：批量选题、素材包、访谈和完整写稿
   +-- dbs-*：标题、开头、逻辑、共鸣、AI 味、对标和发布风险专项
   +-- review / cheat-on-content：发布记录、预测、数据采集和复盘
```

每次自动路由只选择一个主 Skill。一个任务尚未完成时，不讨论下一站；完成后再根据用户的新反馈重新判断。

## 5. 十个子 Skill

| Skill | 主要触发 | 核心产物 | 主要课程来源 |
|---|---|---|---|
| `qcs-positioning` | 定位、人设、内容主线、账号阶段、单条业务目标不清 | 定位卡或单条内容业务位置：用户、价值、人设、类型、风格、目标及证据状态 | 认知准备篇；方向篇定位三课；旧版定位和策划 |
| `qcs-topic` | 收集、筛选或确认一条选题；判断是否值得做 | 带来源选题卡：需求、解决方案、普世入口、新鲜度、证据、预期反应 | 常规爆款与原创流程；创意选题；选题收集和确认 |
| `qcs-outline` | 材料杂乱、观点过多、不知道先讲什么 | 一句话主旨、材料清单、证据缺口、三个以内主要推进节点 | 大纲与材料组织；梳理逻辑框架 |
| `qcs-viewer-path` | 不知道观众为何停留、理解、信任或行动；需要检查完整观看路径 | “被看见—被理解—被信任—采取行动”路径图及可能流失点 | 流量结构；流量漏斗；信息效率 |
| `qcs-structure` | 选题和材料已成立，需要设计钩子、骨架、情绪刺点和持续观看理由 | 开头承诺、信息释放顺序、段落推进理由和反馈点地图 | 钩子、骨架、情绪刺点 |
| `qcs-language` | 表达复杂、术语多、信息重复、口播不像人话 | 大白话版本、必要理解桥梁、语言与画面分工标注 | 文字语言基本功；信息效率；细节雕琢 |
| `qcs-situation` | 内容抽象、只有观点或知识，没有人物和场景 | 情境卡：人物、目标、动作、关系、环境、阻力和事实边界 | 情境化思维 |
| `qcs-story` | 真实材料存在，但过程没有变化或故事动力 | 故事链：变化、目标、行动、阻力、结果、认识变化和不可补造项 | 故事性思维；人物欲望与设置障碍练习 |
| `qcs-visual` | 需要画面、拍摄、镜头、空间、物品、表演或导演风格设计 | 分镜或镜头表：信息任务、视点、景别、动作、空间、物品、光色、声音和素材缺口 | 视频基本功；镜头表现；空间；物品；视觉叙事；导演风格 |
| `qcs-conversion` | 内容要引流、卖产品、处理顾虑或推动行动 | 适用对象、真实卖点、证据、限制、顾虑处理、行动指令和承接路径 | 广告脚本；引流素材；用户、产品与营销 |

### 5.1 首版暂不继续细拆

- 镜头表现、空间调度和物品视觉化先作为 `qcs-visual` 的三个模式；出现高频独立需求后，再考虑拆为新 Skill。
- 时间语法作为 `qcs-visual` 的高级参考；当前校订索引标注“以后再试”，不写成默认流程。
- 短视频带货、本地生活、直播和电商内容体系先作为商业场景参考；出现真实任务后再考虑 `qcs-commerce`。
- “极简 AI 课”转化为所有子 Skill 共用的人机分工规则，不独立建 Skill。
- “政治思维”只保留为立场与安全边界，不建立一个容易误路由的独立 Skill。
- 数据复盘继续使用现有 `review` 和 `cheat-on-content`，不重复创建 `qcs-review`。

## 6. 与现有 Skill 的职责边界

### 6.1 `qcs-topic` 与 `shengcai-topic-generator`

- `qcs-topic`：诊断、选择或完善一条选题，回答“这条为什么值得做”。
- `shengcai-topic-generator`：读取素材库，批量生成、去重并写入候选选题池。

### 6.2 `qcs-outline` 与 `shengcai-content-writer`

- `qcs-outline`：完成写稿前的编导主旨、材料和推进顺序。
- `shengcai-content-writer`：建立素材包、访谈、生成初稿并整理最终发布稿。

### 6.3 `qcs-structure` 与 DBS 专项

- `qcs-structure`：从课程方法出发设计整条作品的结构，并写入编导卡。
- `dbs-hook`：只诊断或优化已有开头。
- `dbs-script-flow`：只检查已有逐字稿的段落衔接、信息密度和划走风险。
- `dbs-resonate`：只检查情绪、立场和共鸣。

QCS 不复制 DBS 的标题公式、开头生成方法或专项诊断量表。

### 6.4 `qcs-conversion` 与发布风险

- `qcs-conversion`：设计真实、可承接的商业行动路径。
- `dbs-content-risk-check`：在准备发布时检查合规、事实和表达风险。

### 6.5 复盘与规则升级

- `review`：建立和维护发布复盘文件。
- `cheat-on-content`：盲预测、评分、发布登记和校准循环。
- `qcs`：读取复盘结论，决定下一条应调用哪个能力 Skill；满足既有升级门槛后才提议更新导演规则。

## 7. 共用上下文和交接契约

每个子 Skill 首先使用当前对话已有信息，不重复询问。只有缺失信息足以改变输出方向时，才一次询问一个关键问题。

主入口向子 Skill 传递：

1. 用户原始请求；
2. 当前最新稿件、选题卡或编导卡；
3. 第一目标与目标观众；
4. 一句话主旨；
5. 用户要求保留或删除的内容；
6. 已确认事实、来源边界和不可新增信息；
7. 本轮只需要完成的一个任务。

子 Skill 返回：

1. 当前判断；
2. 可直接使用的产物；
3. 使用的事实与课程方法来源；
4. 尚缺且会改变方向的信息；
5. 是否已经满足本 Skill 的完成标准。

自动路由不得默认一次串行调用多个子 Skill。用户显式指定多个任务时，先完成当前最早阻塞后续工作的一个。

## 8. 课程真源与读取策略

### 8.1 来源优先级

1. `01_学习对象/安先生/5.0课程逐字稿校订/核心方法校订_v0.1.md`。
2. `01_学习对象/安先生/16-安先生5.0课程学习总览.md`。
3. 旧版七份结构化课题笔记，作为专项补充。
4. 原始逐字稿，仅用于核对当前问题的上下文。

当前只有核心方法校订明确标记为可直接供 Skill 使用。原始逐字稿均未逐句对照音视频，不得直接固化为 Skill 的硬规则。

### 8.2 课程映射

在 `skills/qcs/references/course-map.md` 建立完整映射：

- 38 节 5.0 课程分别归属哪个子 Skill、共用规则或暂缓区；
- 对应结构化笔记路径；
- 校订状态；
- 允许提取的方法和禁止固化的信息。

每个子 Skill 默认只读取自己的映射和对应校订章节，不整批加载课程。

### 8.3 永久排除项

- 课程销售、学员成绩、讲师收入和个人背书；
- 未经当前官方资料核实的平台阈值、后台入口、算法解释和投放规则；
- 课程案例的标题、开头、原句、个人话术和叙事腔调；
- 保证热门、涨粉、成交或收入的绝对结论；
- 无法确认的人名、术语、数字和因果关系。

## 11. 失败与降级处理

- 目标子 Skill 尚未安装：QCS 明确说明缺失项，只完成自身仍能可靠处理的部分，不冒充已经调用。
- 找不到 Vault 根目录或必要文件：列出准确缺失路径，停止写入。
- 课程来源未校订或存在冲突：标记“待确认”，不得根据语感补全。
- 用户已经确认稿件：诊断可以继续，但覆盖或改写前仍需用户确认。
- 多个问题同时存在：优先处理最早阻塞后续工作的一个；如果两种选择会产生不同结果，只问一个关键问题。
- 当前任务已有外部 Skill：路由复用，不创建第二套实现。

## 12. 验证计划

### 12.1 结构验证

- 对 11 个 Skill 逐一运行 `quick_validate.py`。
- 检查所有 frontmatter 名称与目录一致。
- 检查所有相对路径真实存在。
- 检查用户级 Junction 的源和目标一致。
- 更新并运行 `validate-workspace.ps1`。

### 12.2 路由行为测试

至少覆盖：

1. 定位不清 → `qcs-positioning`。
2. 批量生成选题 → `shengcai-topic-generator`，不是 `qcs-topic`。
3. 检查一条选题是否值得做 → `qcs-topic`。
4. 材料杂乱 → `qcs-outline`。
5. 观看路径不清 → `qcs-viewer-path`。
6. 结构设计 → `qcs-structure`。
7. 只改开头 → `dbs-hook`，不是 `qcs-structure`。
8. 表达复杂 → `qcs-language`。
9. 抽象内容情境化 → `qcs-situation`。
10. 真实经历改成故事 → `qcs-story`。
11. 拍摄与分镜 → `qcs-visual`。
12. 广告与引流行动 → `qcs-conversion`。
13. 完整写稿 → `shengcai-content-writer`。
14. 已发布并有数据 → `review` 或 `cheat-on-content`。

### 12.3 边界测试

- 不因课程说法编造平台阈值或官方算法规则。
- 不复制课程标题、话术和案例表达。
- 不覆盖用户确认稿件。
- 不让一个子 Skill 自动串行调用其余九个。
- 不创建第二套内容文件。
- 一条内容数据只产生观察，不直接升级为正式规律。

### 12.4 独立前向测试

完成实现后，用不包含预期答案的真实请求交给独立审查 Agent，验证：

- 能否路由到正确 Skill；
- 能否只加载相关课程方法；
- 能否生成约定产物；
- 能否避开相邻 Skill 的职责；
- 用户中途进入时是否避免重走已有步骤。

## 13. 实施顺序

1. 建立共用交接契约与完整课程映射。
2. 精简 `qcs` 为路由入口。
3. 建立十个子 Skill 及 UI 元数据。
4. 更新安装和工作区验证脚本。
5. 扩充路由、边界和近邻测试。
6. 安装用户级 Junction。
7. 执行结构验证和独立前向测试。
8. 根据测试结果做外科手术式修正。

## 15. 非目标

- 不修改安先生原始逐字稿。
- 不一次性把所有课程案例和正文复制进 Skill。
- 不改造 DBS、shengcai、review 或 cheat-on-content 的内部规则。
- 不改变账号定位、公开范围或用户事实。
- 不修改现有内容稿件、历史预测、复盘和实验记录。

## 16. 完成定义

- `$qcs` 能从真实用户请求中稳定选择一个正确主 Skill。
- 十个子 Skill 均可被独立发现和显式调用。
- 全部 5.0 课题在课程映射中有唯一主要归宿或明确暂缓原因。
- 子 Skill 只加载与当前任务有关的方法。
- 与 DBS、shengcai、review、cheat-on-content 的边界通过近邻测试。
- 安装与验证脚本通过，且不覆盖已有 Skill。
- 原始课程、用户稿件和历史数据均未被改动。
