# QCS 关联检索 02_内容素材设计

## 1. 目标

让 QCS 在制作或诊断一条具体选题时，把 `02_内容素材/` 作为可主动检索的内容素材库，从中寻找与当前选题相关的：

- 内容与案例；
- 信息点与事实线索；
- 原作者观点；
- 金句和表达素材。

检索结果用于增强选题判断和后续大纲，不把每次单条创作变成全库扫描。

## 2. 已确认边界

### 2.1 单条选题主动检索

`qcs-topic` 在以下情况主动检索 `02_内容素材/`：

- 用户正在制作或诊断一条具体选题；
- 已有方向，但需要案例、观点或信息点补强；
- 需要判断素材库里是否已有可复用材料。

先根据选题关键词、相关概念、用户问题和解决方案做文本检索，再读取命中的少量相关素材。没有明确关联时不整库加载。

### 2.2 有效素材规则

沿用当前 Vault 的素材规则：

- 排除 `搜索关键词.md`、`_入库检查报告.md` 和其他文件名以 `_` 开头的辅助文件；
- 优先使用同时具备真实标题、来源链接和可读正文的素材；
- 图片影响选题或信息理解时，按笔记中的嵌入顺序查看；
- 图片是素材内容的一部分，主要来源仍记录对应 Markdown 笔记路径。

素材缺少来源或正文时，可以列为线索，但不得作为已核实事实使用。

### 2.3 金句处理

素材分析允许两种输出并列存在：

1. **内部原文摘录**：可以摘出素材中的短句，保留原文和具体来源路径，只用于理解、比较和改写，不直接进入发布初稿。
2. **改写候选**：在不改变原意的前提下，改成符合当前账号定位和用户表达习惯的版本；只有这一层可以进入初版正文。

内部不得丢失摘录来源，也不把原作者原句标记为用户原创。进入最终发布稿前，用户可以继续调整；QCS 也可以协助把候选改成真正符合用户观点和语言习惯的表达。

### 2.4 事实与观点分层

检索结果必须区分：

- 素材记录的事实或案例；
- 原作者的观点或判断；
- 内部原文摘录；
- QCS 根据材料提出的关联分析；
- 尚待确认的信息。

采用的内容保留具体素材路径或原始链接。仅来自中文二次整理的重要事实，继续按当前定位规则标记来源状态，不包装成独立核验结论。

## 3. 与现有 Skill 的分工

- `qcs-topic`：围绕当前一条选题检索少量相关素材，并产出可追溯选题卡。
- `qcs-outline`：优先使用 `qcs-topic` 已选中的素材清单；用户明确要求或出现材料缺口时，才补充检索，不默认重扫全库。
- `shengcai-topic-generator`：继续负责全库盘点、批量生成、去重和写入选题池。
- 其他 `qcs-*`：接收已经选中的素材和来源，不默认独立扫描 `02_内容素材/`。

不新增 `qcs-material` 子 Skill，避免为一次检索增加额外路由层。

## 4. 交互与异常处理

- 当前对话已经说明选题方向时直接检索，不重复询问。
- 多个素材的同名概念、事实或观点相互冲突，而且会改变选题方向时，只问用户一个关键问题。
- 找不到相关素材时明确报告“素材库暂无明显相关内容”，继续使用用户已提供材料，不强行建立关联。
- 无法识别图片、来源链接失效或正文缺失时，报告准确文件路径和影响，不猜测内容。

## 5. 文件改动范围

实施时只修改：

1. `skills/qcs/references/shared-contract.md`：增加 `02_内容素材/` 的共用来源、内部原文摘录与改写规则。
2. `skills/qcs-topic/SKILL.md`：增加单条选题的相关素材检索流程和选题卡字段。
3. `skills/qcs-outline/SKILL.md`：说明优先继承已选素材，缺口明确时才能补检索。
4. `skills/qcs/evals/evals.json`：增加素材检索、辅助文件排除、金句来源和无结果降级场景。

不修改 `02_内容素材/` 内任何文件，不改变 `shengcai-topic-generator` 的批量流程，也不修改现有选题、正文或复盘。

## 6. 验收标准

- 一条具体选题可以触发对 `02_内容素材/` 的相关性检索。
- 检索只读取命中的相关素材，不默认加载全库。
- 辅助文件不会进入内容来源。
- 采用的案例、信息点、观点和金句都保留具体路径。
- 内部原文摘录与改写候选明确区分，只有改写候选进入初版正文。
- 没有匹配素材时能够正常降级，不编造关联。
- `qcs`、`qcs-topic` 和 `qcs-outline` 继续通过结构与工作区验证。
