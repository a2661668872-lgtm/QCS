# QCS（请出山）升级设计规格

## 目标

在不建立第二套编导系统的前提下，把现有编导 Skill 统一命名为 `qcs`，显示名称为“QCS（请出山）”。

它负责把账号目标、选题、证据、主旨、大纲、画面、写稿、发布和复盘连成一条短视频工作流；遇到开头、节奏、共鸣、AI 味、标题或发布风险等专项问题时，转入对应 DBS Skill，而不是在本 Skill 中复制一套诊断规则。

## 复用范围

保留并升级以下现有文件，不创建同功能的新 Skill：

- `skills/qcs/`
- `07_AI编导系统/`
- `skills/shengcai-content-writer/`
- `skills/review/`

内部 Skill 名称与文件夹统一使用 `qcs`，实际调用方式为 `$qcs`；现有项目引用和安装脚本同步迁移。

## 问题契约

- 反复出现的问题：已有选题、素材或草稿，但 AI 容易直接写全文，导致选题判断、材料组织、商业目标、画面设计和真实表达混在一起。
- 典型使用情境：用户准备创作或检查一条短视频，当前材料可能停留在想法、选题、素材、初稿、最终稿、已发布或已有数据中的任一阶段。
- 用户想推进的变化：先完成编导判断，再调用合适工具执行，不重复已确认步骤。
- Skill 需要交付的结果：一份可追溯的编导卡，以及当前阶段所需的大纲、画面、写稿路由、发布记录或复盘动作。
- 完成证据：能正确识别当前阶段；明确一条内容的目标观众、问题、第一目标、目标变化、主旨、证据、大纲和画面；专项问题能够路由到正确 DBS Skill；不编造事实，不照搬课程表达。
- 不处理的近邻问题：不替代素材入库、完整写稿、标题专项优化、发布风险审核和发布复盘等已有 Skill。

## 三层架构

### 1. 编导决策层

由 QCS（请出山）负责：

- 判断内容处于哪个阶段。
- 明确内容在业务路径中的位置。
- 确认目标观众、具体问题和唯一主要任务。
- 区分本人事实、来源说法、本人判断、课程方法和待核查信息。
- 先整理一句话主旨、材料清单、大纲和画面，再进入全文。
- 发布后把单条结果记为观察，不直接升级成账号规律。

### 2. 专项诊断层

保持 DBS 独立，通过任务问题路由：

| 具体问题 | 使用的 DBS Skill |
| --- | --- |
| 选择或检查对标 | `dbs-benchmark` |
| 检查内容是否讲清楚 | `dbs-content` |
| 优化短视频开头 | `dbs-hook` |
| 检查段落衔接、信息密度和划走点 | `dbs-script-flow` |
| 增强情绪与共鸣 | `dbs-resonate` |
| 检查 AI 写作痕迹 | `dbs-ai-check` |
| 生成小红书标题 | `dbs-xhs-title` |
| 检查发布风险 | `dbs-content-risk-check` |

QCS（请出山）只说明为什么需要转入某个专项任务，并传递必要材料；不在自身规则中复制 DBS 的方法。

### 3. 文件与闭环层

- `shengcai-content-writer`：素材包、访谈、初稿、用户修改和最终发布稿。
- `review`：发布记录、真实数据、轻复盘和下一篇调整。
- `07_AI编导系统`：编导卡、课程方法、实验假设和已验证导演规则。

不建立第二套素材包、复盘文件、评分表或受众画像。

## 工作流

1. 读取定位、当前导演规则和任务对应文件。
2. 判断当前阶段，不要求用户重走已完成步骤。
3. 建立或补全单条编导卡。
4. 先确认内容的第一目标、目标变化和一句话主旨。
5. 整理证据与材料，删除无关支线。
6. 生成三个以内的主要推进节点。
7. 设计每一段由口播、人物、动作、空间、道具、录屏或数据图中的哪一种承担信息。
8. 需要写全文时转入 `shengcai-content-writer`。
9. 出现明确专项问题时转入对应 DBS Skill。
10. 最终稿完成后进入拍摄、发布和 `review` 复盘。
11. 单条结果进入实验假设；满足既有升级门槛后，才提议修改正式规则。

## 5.0 课程使用与校音

### 首版范围

第一版只校对会直接支持编导工作的核心课程，不一次性校对全部 38 节：

- 方向篇：定位、人设、常规选题和创意选题。
- 基本功篇：视频与语言、镜头表现、空间、物品视觉化、大纲和内容复盘。
- 进阶篇：流量漏斗、信息效率、结构、情境、故事、画面和导演风格。

特殊专题篇暂不进入首版共同规则；真实任务涉及带货、本地生活、直播或电商时再按需校对和读取。

### 来源优先级

1. 已整理并注明边界的结构化课程笔记。
2. 5.0 原始逐字稿，用于核对上下文。
3. 用户后续提供的原视频、完整正文或人工校音结果。

结构化笔记与原始逐字稿冲突时，不根据语言习惯猜测讲师原意。

### 校音规则

- 可以修正能够明确判断的错别字、同音字、英文工具名、标点和断句。
- 不确定的人名、术语、数字、平台规则和因果结论标记为“待确认”。
- 不把讲师的经验判断改写成平台官方规则。
- 不改变课程原意，不为了让语言更漂亮而重写观点。
- 原始逐字稿继续保留；校订结果单独存放，并记录原始文件路径和校订状态。
- Skill 只读取已校订或已结构化的规则；未校订原文只用于核对，不直接转化为硬规则。

### 校订产物

在 `01_学习对象/安先生/5.0课程逐字稿校订/` 中按原有篇章和文件名保存核心课程校订版，并建立 `_校订索引.md`，记录：

- 原始文件；
- 校订文件；
- 状态：已校订／部分校订／待确认；
- 仍不确定的词句；
- 是否已进入 Skill 方法库。

不得覆盖 `01_学习对象/安先生/5.0课程逐字稿/` 中的原始文件。

## 方法进入 Skill 的门槛

一条课程方法只有同时满足以下条件，才能写进 Skill 的共同规则：

1. 能改变一个具体编导判断或输出。
2. 能用大白话说明适用情境。
3. 已排除明显 ASR 错字或上下文缺失。
4. 不依赖过时的平台阈值、工具入口或绝对算法判断。
5. 不复制课程案例、标题、开头、话术和个人表达。

尚未满足条件的方法保留在课程笔记中，不写进主入口。

## 修改内容

本轮预计只修改或新增：

- 更新 `skills/qcs/SKILL.md` 的名称展示、DBS 路由、课程读取和校音边界。
- 更新 `skills/qcs/agents/openai.yaml` 的显示名称与默认调用语句。
- 必要时增加一个课程方法 reference，避免主入口过长。
- 在 `01_学习对象/安先生/5.0课程逐字稿校订/` 新建核心课程校订文件和索引。
- 必要时更新 `07_AI编导系统/AI编导总纲.md` 中的三套能力分工，但不改写历史实验和预测。

不修改 DBS 官方 Skill，不覆盖用户稿件、课程原始逐字稿和历史复盘。

## 验证样本

首版使用 4 类任务验证：

1. 正常样本：从已有选题和素材建立编导卡，并给出大纲和画面。
2. 中途样本：已有初稿，只检查缺失的编导环节，不要求从头创作。
3. 专项样本：用户只要求优化开头或检查 AI 味，能够转入正确 DBS Skill。
4. 边界样本：课程原文存在疑似错字或不确定平台结论时，能够标记待确认，不猜测、不升级为规则。

## 完成标准

- 显示名称为“QCS（请出山）”，调用名称为 `$qcs`，项目引用完成迁移。
- Skill 结构校验通过。
- 项目内所有相对引用真实存在。
- 至少完成一个真实主任务的行为冒烟测试。
- DBS 分工清楚，没有复制专项 Skill 的规则。
- 原始课程文件没有被覆盖。
- 核心课程校订索引能够看出已处理范围和待确认项。
