# shengcai-pattern-extractor 设计规格

## 目标

创建可重复调用的 Codex Skill `shengcai-pattern-extractor`，显示名称为“航海规律提取助手”。它负责从 Obsidian Vault 的 `02_内容素材` 增量维护内容汇总和标题、开头、正文结构三类规律文件，同时保留用户已确认的规律。

- 个人安装目录：`C:\Users\JT\.codex\skills\shengcai-pattern-extractor\`

## 触发范围

Skill 应在以下请求中触发：

- 从 `02_内容素材` 提取标题、开头、图片正文和正文结构；
- 生成或更新 `_规律提取汇总.md`；
- 生成或更新标题、开头和正文结构规律；
- 用户说“我搜集了新内容，帮我更新内容规律”；
- 用户要求增量补强已有规律，同时保留已确认内容。

## 核心工作流

1. 读取项目配置和个人定位文件。
2. 运行只读盘点脚本，识别候选素材、有效素材、图片引用、已处理素材和新增素材。
3. 首次运行时处理全部有效素材；增量运行时只处理新增路径或新增视频 ID。
4. 对每条新增素材提取素材路径、标题、笔记文字开头、图片内容开头、图片正文和正文结构。
5. 按嵌入顺序读取全部本地图片；读取失败时记录具体路径，不猜测图片文字。
6. 写入或增量更新 `03_内容规律/_规律提取汇总.md`。
7. 将新增素材与现有标题、开头和正文结构规律比较：
   - 同一种做法至少有两条来源时进入候选规律；
   - 只有一条来源时进入单条观察；
   - 已有规律获得新证据时只追加来源或补强证据。
8. 保留用户已确认的规律、状态和已删除区域，不擅自改写、降级、恢复或删除。
9. 更新三份规律文件末尾的待确认清单，并报告新增素材、规律变化和无法读取项。

## 增量识别

`inventory_materials.py` 使用 Python 标准库，只读扫描 Vault：

- 排除 `搜索关键词.md`、`_入库检查报告.md` 和其他以 `_` 开头的辅助文件；
- 解析标题、来源链接、视频 ID、`## 正文` 和 Obsidian 图片嵌入；
- “未提供”不算可读正文；
- 从 `_规律提取汇总.md` 的“素材文件”字段取得已处理路径；
- 同时用视频 ID 防止文件改名后被误判为新增；
- 以 JSON 输出全部、有效、无效、新增素材和图片引用；
- 不修改任何 Vault 文件。

## 已确认规律保护

三份规律文件中的以下内容视为受保护：

- 状态为“本期可用”“以后再试”或“已删除”的规律；
- 文档末尾“已删除”区域及其删除原因；
- 用户明确标记为已确认的文字。

新增素材可以为受保护规律追加来源证据，但不能改变其名称、解释、适用范围、状态或删除原因。需要改变时必须先获得用户明确确认。

## 输出规范

`references/output-contract.md` 保存两类固定结构：

- 汇总底稿的四字段结构，以及图片正文、图片开头和不可读路径的记录方式；
- 三份规律文件的候选规律、单条观察、状态、已删除和待确认格式。

Skill 不写无法由素材证明的因果结论；任何改写内容必须标注“AI 示例”。

## 错误处理

- 素材缺少标题、来源链接或可读正文：记录为无效，不补写。
- 图片不存在或无法读取：记录完整路径，继续处理其余素材。
- 汇总或规律文件不存在：按输出规范新建。
- 现有文件结构无法识别：停止覆盖，报告冲突并请求用户处理。
- 发现已确认规律可能需要调整：保留原文，只加入待确认清单。

## 验证

1. 使用 `skill-creator/scripts/quick_validate.py` 校验项目源 Skill。
2. 对当前 Vault 运行盘点脚本，预期识别 11 条有效素材、0 条新增素材和 1 个本地图片引用。
3. 安装到个人 Codex Skills 目录。
4. 再次运行 `quick_validate.py` 校验安装目录。
5. 比较项目源和个人安装目录中对应文件的 SHA-256，确认安装内容一致。

## 非目标

- 不自动修改原始素材。
- 不自动核验视频中的事实、数字或平台效果。
- 不自动确认候选规律。
- 不根据规律生成选题或脚本。
- 不实现图片 OCR 程序；图片文字由具备视觉能力的 Agent 实际读取。
