# shengcai-topic-generator 设计说明

## 目标

创建可重复使用的 Codex Skill `shengcai-topic-generator`，显示名称为“航海选题助手”。它根据 Obsidian Vault 中已确认的账号定位和真实内容素材，首次生成候选选题，并在后续只处理新增素材、去重后追加新选题。

Skill 源文件先保存在当前项目的 `skills/shengcai-topic-generator/`，通过校验后再安装到个人 Codex Skills 目录。

## 目录结构

```text
skills/shengcai-topic-generator/
├── SKILL.md
├── agents/
│   └── openai.yaml
├── scripts/
│   └── inventory_materials.py
└── references/
    └── output-contract.md
```

- `SKILL.md`：定义首次生成、增量生成、图片读取、去重和保护规则。
- `agents/openai.yaml`：保存显示名称、简短说明和默认调用提示。
- `scripts/inventory_materials.py`：只读盘点有效素材、已读取素材、新增素材和本地图片引用。
- `references/output-contract.md`：定义选题字段、素材状态、已读取素材和追加格式。

不创建 README、安装说明、更新日志或其他辅助文件。

## 有效素材

读取 Vault 根目录的项目配置和 `00_个人背景/定位总览_v0.1.md`。

盘点 `02_内容素材` 时：

1. 排除 `搜索关键词.md`、`_入库检查报告.md` 和其他文件名以 `_` 开头的辅助文件。
2. 只有同时具备真实标题、来源链接和可读正文的内容才算有效素材。
3. 字段为空或值为“未提供”时，视为缺失。
4. 本地图片按 Markdown 嵌入顺序列出，由 Codex 的视觉读取能力逐张查看；图片文字只用于理解内容，不作为独立来源路径。
5. 图片缺失、损坏或无法读取时，记录具体路径，不跳过、不推测。

首次生成前，有效素材不足 10 条时停止，不创建或修改选题池，并报告还缺多少条。

## 首次生成流程

当 `04_选题库/选题池.md` 不存在或没有“已读取素材”记录时，执行首次生成：

1. 读取定位和全部有效素材，包括本地图片文字。
2. 结合目标读者、账号价值、内容范围和暂时不做的内容筛选方向。
3. 生成 5—10 个候选选题，优先选择当前材料能够讲清楚的方向。
4. 每个选题只说明准备讲什么，不优化成夸张标题，不生成开头、结构或正文。
5. 每个选题记录具体受众、具体问题、准备讲什么、素材状态、缺少什么和真实素材文件路径。
6. 在文末创建“已读取素材”，记录本轮全部有效内容文件路径。

如果关键数字、人物、公司或方法只来自中文二次整理，选题可以保留，但必须标记“缺素材”，并写清仍需补充的本人视频、采访、品牌官网、公开账号或数据依据。

## 增量生成流程

当用户说“我搜集了新内容，帮我生成新选题”或表达相同意图时，执行增量模式：

1. 读取定位、当前选题池和 `02_内容素材`。
2. 以素材路径、笔记或视频 ID、来源链接任一已出现作为已处理依据，防止文件改名后重复处理。
3. 只读取尚未处理的新有效素材及其本地图片。
4. 将新材料提出的受众、问题、核心内容与全部既有选题比较，进行语义去重。
5. 不能通过更换工具名、数字、案例人物或近义表达制造新选题。
6. 新内容足够时追加 5—10 个不同选题；不足时只追加真正成立的数量并说明原因；没有合格新选题时不追加选题，但仍记录已经成功读取的新素材，避免下次重复处理。
7. 新选题从现有最大编号继续编号，并插入现有“已读取素材”区域之前，不重排旧编号。
8. 将本次新读取的素材追加到现有“已读取素材”列表，不重复记录；除插入新内容外，不改写原有行。

## 已有内容保护

把选题池中的所有既有选题默认视为用户已经确认的内容：

- 不删除、不覆盖、不改写、不重排、不重新编号。
- 不改变既有选题的素材状态和来源。
- 即使新材料能补强旧选题，也不直接修改旧选题；需要时在执行报告中说明可补强方向，等待用户决定。
- 只在“已读取素材”区域之前插入新选题，并在该区域内追加新的素材路径；原有选题和素材记录保持原样。

## 输出约定

每条选题使用以下字段：

```markdown
## 选题 01：准备讲什么

- 准备写给谁：
- 解决的具体问题：
- 准备讲什么：
- 素材状态：材料基本够用 / 缺素材
- 缺少什么：无 / 具体缺失内容
- 主要来源：
  - `02_内容素材/.../笔记信息.md`
```

文末保留：

```markdown
## 已读取素材

- `02_内容素材/.../笔记信息.md`
```

选题名称保持中性、清楚，只表达内容范围；不得使用“必爆”“神级”“一定赚钱”等无法由素材证明的包装。

## 错误处理

- 定位文件缺失：停止并报告具体路径。
- 有效素材不足 10 条：停止并报告有效数量与缺口。
- 图片无法读取：记录具体路径；判断该图片是否影响理解，影响时相应选题标记“缺素材”。
- 选题池格式无法识别：不重写文件，报告需要人工确认的格式问题。
- 没有新增有效素材：不修改选题池，报告盘点结果。
- 新素材与既有选题全部重复：不凑数、不追加选题，只把新素材路径追加到“已读取素材”并说明重复原因。

## 验证标准

1. 使用 Skill Creator 的 `quick_validate.py` 验证项目源文件。
2. 运行盘点脚本，确认当前 Vault 能识别 14 条有效素材、8 条既有选题和 14 条已读取素材。
3. 验证当前状态下增量模式识别为没有新增素材。
4. 使用临时测试 Vault 模拟首次生成前盘点、新增素材识别、路径改名但 ID 或链接相同、无效素材排除和图片引用识别。
5. 安装后再次运行 `quick_validate.py`。
6. 对比项目源目录与个人安装目录的文件清单和文件哈希，确认安装副本一致。

## 安装边界

项目源文件验证通过后，复制到个人 Codex Skills 目录的 `shengcai-topic-generator` 文件夹。安装前确认目标不存在；如果已存在，不直接覆盖，先停止并报告冲突。

当前项目不是 Git 仓库，因此设计文档和 Skill 源文件无法提交；本任务以文件创建、脚本测试、官方校验和安装副本一致性校验作为完成标准。
